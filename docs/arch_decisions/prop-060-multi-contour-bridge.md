# PROP-060: Мультиконтурная архитектура (Contour Bridge)

> **Статус:** 🧩 Предложение (vision) — Мультиконтурная архитектура (Contour Bridge): шлюз между контурами, обезличивание, аудит
> **Дата:** 2026-10-08
> **Источник:** перенесено из `AD-DRAFTS.md` (D15; черновик 2026-09-16); Roadmap Фаза 2.
> **Связано:** [ADR-036](./adr-036-llm-gateway.md), [ADR-042](./adr-042-hybrid-mode.md),
> [PROP-050](./prop-050-external-engines-runner.md), [PROP-055](./prop-055-instance-exchange.md),
> [PROP-061](./prop-061-llm-security-layers.md), [ADR-099](./adr-099-egress-tls-trust.md).

**Решение:** `ContourBridge` (на базе Runner, [PROP-050](./prop-050-external-engines-runner.md)) —
единый шлюз между **контурами** (изолированными средами/сетями, например внешний и внутренний контур).
Bridge отвечает за транспорт, обезличивание данных на границе и аудит.

Состав:

- **Транспорт** между контурами — Kafka/RabbitMQ.
- **Политики обезличивания** — правила маскирования персональных/чувствительных полей
  (`ip`, `phone`, `email`, `fio`, `contract`).
- **Audit-topic** — отдельный неизменяемый поток аудита обмена (без права очистки).
- **Release/feedback pipeline** — перенос релизов и сбор обратной связи между контурами.
- **UI-индикатор контура** — отображение, в каком контуре находится пользователь/сущность.

Сущности `ContourRelease`, `ContourTestResult`, `ContourIssue` — в `@itphx/synth-shared`; секция
`contour` — в `config.yaml`.

## Контекст

**Зачем контуры.** В ряде заказчиков внешний и внутренний контуры физически/сетево разделены, и
данные нельзя переносить как есть: на границе требуется обезличивание и аудит. Прямого канала между
контурами нет — нужен контролируемый шлюз.

**Почему на базе Runner.** Runner ([PROP-050](./prop-050-external-engines-runner.md)) задуман как
транспортно-агностичный gateway с адаптерами; ContourBridge — его специализация для межконтурного
обмена (та же идея «мост наружу», другой транспорт и политики).

Сегодня в Synth нет ничего из этой области — концепция существует только в Roadmap Фаза 2.

## Детали

### 1. ContourBridge

Сервис-шлюз: приём сообщений из источника, применение политик, передача в целевой контур, публикация
в audit-topic. Реализуется поверх инфраструктуры Runner.

### 2. Транспорт

Зависит от целевых контуров: **Kafka** vs **RabbitMQ** — открытый вопрос (что доступно у заказчиков).
Абстракция транспорта, чтобы не привязываться к брокеру.

### 3. Обезличивание

Правила маскирования по типам данных:

| Тип | Пример маскирования |
|---|---|
| `ip` | `192.168.x.x` |
| `phone` | `+7***…` |
| `email` | `a***@…` |
| `fio` | маска ФИО |
| `contract` | маска номера договора |

Владелец правил — открытый вопрос (per-contour config).

### 4. Аудит

Отдельный **audit-topic** без права очистки: все межконтурные операции фиксируются неизменяемо.
Согласуется с неизменяемостью аудита в [PROP-061](./prop-061-llm-security-layers.md) и Gateway
([ADR-036](./adr-036-llm-gateway.md)).

### 5. Пайплайны

- **Release pipeline** — доставка релиза из внутреннего контура во внешний.
- **Feedback pipeline** — обратный поток (issues, результаты тестов).

Сущности: `ContourRelease`, `ContourTestResult`, `ContourIssue` (shared).

### 6. UI-индикатор

Отображение активного контура в UI, чтобы пользователь понимал, где он работает и куда уходят данные.

### 7. Конфигурация

Секция `contour` в `config.yaml` (через `@itphx/synth-shared/config`, приоритет
CLI > env > yaml > defaults, [ADR-023](./adr-023-configuration.md)).

## Статус реализации в коде

**Не реализовано.** Проверено по репозиторию (grep по `packages/**`, исключая `dist/` и `node_modules/`):

- `ContourBridge` и сущности `ContourRelease` / `ContourTestResult` / `ContourIssue` в коде и в
  `@itphx/synth-shared` отсутствуют.
- Транспорт Kafka/RabbitMQ в зависимостях нет; политик обезличивания нет; audit-topic нет;
  UI-индикатора контура нет; секции `contour` в конфиге нет.
- Единственное совпадение на «Kafka» — строка-пример в тесте micro-классификатора
  (`packages/core/src/engine/router/micro/index.test.ts`), к Contour Bridge отношения не имеет.
- Базы Runner нет — компонент не реализован (план: [PROP-050](./prop-050-external-engines-runner.md)).

## Открытые вопросы

- Kafka vs RabbitMQ — что доступно в целевых контурах?
- Кто владеет правилами обезличивания (per-contour config или централизованно)?
- Формальная модель контуров (внешний/внутренний; сколько их; как помечаются сущности)?
- Как ContourBridge соотносится с обменом между инстансами
  ([PROP-055](./prop-055-instance-exchange.md)) — разные сценарии или общий слой?
- Неизменяемость аудита — WORM-хранилище?
