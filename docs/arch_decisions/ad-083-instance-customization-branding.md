# AD-083: Кастомизация инстанса и брендинг (приветственное окно, подпись, ватермарка)

> **Статус:** ⏳ Не реализовано (предложение)
> **Дата:** 2026-10-02
> **Источник:** согласовано 2026-10-02 — предпосылка демо-портала (`synth-control`, AD-001).
> **Связано:** [AD-072](./ad-072-settings-ui-kit.md), [AD-023](./ad-023-configuration.md).

**Решение:** добавить в Synth механизм **кастомизации инстанса**:

- **приветственное окно** после первого входа с возможностью **повторного вызова** (меню/справка);
- **конфиг брендинга инстанса**: название, лого/подпись, ватермарка на фоне (и, при необходимости,
  акцент/тема);
- **серверная выдача** конфига брендинга, потребление в UI.

## Контекст

- Логотип и название **зашиты в код**: `components/ui/SynthLogo.tsx` (inline-SVG с фиксированным
  path, пропсы только `className/width/height`), `lib/i18n/messages/ru.ts`/`en.ts` (`app.title`),
  fallback в `Header.tsx`, `index.html`, `public/manifest.webmanifest`.
- **Приветственного окна/онбординга нет**: пустое состояние центральной панели —
  `components/CenterPanel.tsx` (лого + `app.title` + `app.subtitle` + `center.noTabs`). Пункта
  «Справка/О программе» и флага «первый вход» нет.
- **Механизм кастомных тем есть, но не наполнен**: UI дергает `GET /api/config/themes`
  (`contexts/ThemeSystemContext.tsx`, `reloadCustomThemes`), а сервер отдаёт пустышку
  `{ themes: [] }` (`packages/core/src/server/app.ts`, `packages/backend/src/app.ts`).
- Конфиг UI (`uiConfigSchema`) содержит только `port/backendUrl/theme/themeMode/locale` — полей
  брендинга нет.
- Единого источника бренд-токенов нет: UI (oklch/flexoki, IBM Plex Mono), лендинг (`#c33b04`,
  JetBrains Mono), доки (Material, JetBrains Mono) — три системы.

## Решение

### 1. Конфиг брендинга

- Новая секция в `shared` (`config/types.ts` + defaults): `branding` (название, подпись, лого,
  ватермарка; при необходимости — акцент/тема). Приоритет — CLI > `SYNTH_*` env > config.yaml >
  defaults (AD-023).
- Поля — **не секреты**; лого/ватермарка — из доверенного источника/встроенных пресетов, без
  произвольной загрузки на первом этапе.

### 2. API конфига брендинга

- `GET /api/config/branding` (core + backend, по образцу `/api/config/themes`) — отдаёт
  «безопасное» подмножество; UI читает при старте.
- Роут доступен без авторизации (как тема/манифест) или с публичным подмножеством — решить в
  реализации.

### 3. UI

- Параметризация `SynthLogo` (подпись/лого), динамические `title`/favicon/`manifest` — из конфига.
- **Ватермарка** — отдельный компонент в layout (фон/оверлей), не мешает читаемости контента и
  корректно ведёт себя в светлой/тёмной темах и на мобильных.
- `WelcomeDialog`: показ после первого входа; **повторный вызов** — пункт меню/настройки
  («Справка»/«О программе»). Содержимое — i18n + брендинг.
- Факт «просмотрено»: предпочтительно в профиле пользователя (синхронизация между устройствами),
  `localStorage` — как fallback.
- i18n-ключи в `ru`/`en`.

## Безопасность

- Лого/ватермарка — только из доверенных источников/встроенных пресетов; санитайз SVG/URL; никаких
  внешних трекеров.
- Конфиг брендинга не должен раскрывать секреты/внутренние адреса.

## Этапы

1. Конфиг `branding` + `GET /api/config/branding`.
2. Параметризация лого/названия/favicon/manifest + ватермарка.
3. `WelcomeDialog` + повторный вызов.
4. (позже) единый источник бренд-токенов для UI, лендинга и доков.

## На потом: блокировка отдельных настроек даже для администраторов инстанса

Отдельным анализом (не в этом AD) проработать **locked settings** — серверную политику, которая
фиксирует часть настроек инстанса и запрещает их менять **даже ADMIN инстанса**:

- какие настройки блокируемы (провайдеры/модели, брендинг, LLM gateway, tools/MCP/skills,
  workspace, permissions);
- где хранится политика и как применяется в core + backend (API-гейт) и в UI (read-only);
- как это соотносится с режимами инстанса (standalone — ADMIN) и с серверным enforcement;
- опираться на [AD-073](./ad-073-client-integrity-hybrid.md) (клиент недоверенный, enforcement на
  сервере), [AD-080](./ad-080-managed-hybrid-modes.md) (managed-режимы),
  [AD-081](./ad-081-hybrid-policy-leak-protection.md) (политики и защита от утечек),
  [AD-025](./ad-025-plan-act-toggle.md)/[AD-029](./ad-029-granular-permissions.md) (permissions).

Актуальность: демо-инстанс под управлением пользователя-ADMIN может менять настройки в обход
внешних ограничений; для демо/enterprise/paid нужен способ жёстко фиксировать критичные настройки.

## Открытые вопросы

- Формат лого/ватермарки: встроенные пресеты vs URL; лимиты размеров/форматов.
- Где хранить «welcome seen» — профиль или localStorage.
- Насколько глубоко параметризовать favicon/manifest (динамика из конфига).
- Нужна ли загрузка пользовательского логотипа и её безопасность (на первом этапе — скорее нет).
- Границы locked settings: какие разделы, какие роли, как быть со standalone.
