# ADR-123: Связь с сервером — фазовое состояние, гейт входа и офлайн-UX

> **Статус:** ✅ Реализовано
> **Дата:** 2026-11-05
> **Парные документы (as-built):** [packages/ui/AGENTS.md](../../packages/ui/AGENTS.md) («Транспорт»), [MESSAGE_FLOW.md](../MESSAGE_FLOW.md) §6.8 «Потеря и восстановление связи».
> **Связано:** [ADR-024](./adr-024-eventhub-transport.md) (единый транспорт), [ADR-118](./adr-118-message-stream-v2.md) (события и догон по `since`), [ADR-044](./adr-044-mobile-adaptive-ui-pwa.md) (PWA / мобильный адаптив), [ADR-041](./adr-041-llm-error-taxonomy.md) (i18n-ключи вместо строк), [ADR-043](./adr-043-unified-identity-login.md) (единый вход/OIDC).

## Контекст и проблема

В PWA (managed-инстанс, OIDC) недоступность сервера выглядела как **ошибка пользователя**, а не как
потеря связи. Наблюдались четыре симптома:

1. **Форма входа вместо «сервер недоступен».** Сетевой сбой/таймаут `GET /auth/status` трактовался как
   «гость», и на managed-инстансе открывалась форма с полем «API ключ» — пользователь видел ветку
   полей, которой у него нет (OIDC-вход), и выглядел разлогиненным.
2. **Модалка «Связь не восстановлена / Обновить страницу?».** Модальный confirm перекрывал интерфейс
   и оставался висеть после того, как связь уже вернулась.
3. **Тосты «Связь с сервером потеряна…» / «Нет подключения к сети».** Появлялись при возврате из фона
   (PWA), когда обрыв был уже устранён, — шум без действия.
4. **Воспроизводимость без потери сети.** Достаточно зависшего `/api/v2/meta`: запрос без дедлайна
   держал старт приложения в «Загрузка…» бесконечно, а отсутствие heartbeat-детекта оставляло UI на
   «зомби»-соединении с открытым сокетом.

Корень: у UI не было **модели связи**. Булев `connected` не различал «первое подключение» и «потерю
связи», сетевые ошибки смешивались с отказом в аутентификации, а у HTTP-запросов не было дедлайнов.

## Решение

1. **Гейт входа — четыре фазы** (`authPhase` — источник истины для `AuthGate`):
   `checking` (спиннер) | `authenticated` | `guest` (форма входа) | `unreachable` (экран «Сервер
   недоступен» + «Повторить»). Сетевая ошибка/таймаут **не** делает пользователя гостем: известные
   возможности сервера (`deployment`/`oidcEnabled`/`debugMode`) сохраняются в
   `localStorage: synth-ui.server-caps.v1` и на холодном старте, поэтому форма с неверной веткой
   полей не показывается. `retry()` идёт с backoff 2,5/5/10/20/30 с — и для сетевых ошибок, и для
   HTTP 5xx от `/auth/status`; индекс сбрасывается **только при успехе** (иначе серия 5xx
   повторялась бы каждые 2,5 с штормом). Событийные повторы (`online`/`visibilitychange:visible`)
   ограничены анти-штормом: не чаще одного раза в 2,5 с; параллельные попытки исключены.
2. **Состояние связи — отдельная фаза** (`transportStore.phase`): `connecting | online |
   reconnecting | offline` + `phaseSince` + `hasEverConnected`. `phase` различает первое подключение
   и потерю связи; `connected` сохранён для совместимости. `restart()` (кнопка «Повторить»)
   публикует `reconnecting`, а не потерю; `manual` (выход) → `connecting`; события браузера
   `offline`/`online` двигают фазу немедленно, не дожидаясь backoff-тика.
3. **Дедлайны запросов** (`lib/api/base.ts`): дефолт **15 с — только для идемпотентных
   чтений** (`GET`/`HEAD`); `POST`/`PUT`/`PATCH`/`DELETE` без явного `timeoutMs` идут **без**
   дефолтного таймаута (бэкап, миграции, установка плагина, консолидация памяти идут минутами —
   обрыв по таймеру оставлял бы сервер работать «в пустоту»). Явный `timeoutMs` работает для любого
   метода, внешний `AbortSignal` (git-клоны, загрузка вложений) по-прежнему означает «управляет
   вызывающий». Явные дедлайны: `/auth/status` — 8 с, `/api/v2/meta` и `/health` — 5 с, отчёты
   аналитики и `maintenance` (`getStatus`/`getDoctor`, проба БД) — 60 с, `logout` — best-effort 5 с
   (ошибка/таймаут глушится: выход не должен «висеть»). Признак «это сеть, а не ответ сервера» —
   единый `isNetworkError()` (`lib/api/errors.ts`: `AbortError`/`TimeoutError`/`TypeError`/известные
   тексты).
4. **Транспорт: pong-watchdog, таймаут рукопожатия и два потолка backoff.** Нет ни одного кадра
   (включая `pong`) за **30 с** → обрыв с причиной `heartbeat` и немедленный реконнект (не ждём,
   пока браузер заметит мёртвый сокет). Сокет, зависший в `CONNECTING` дольше **10 с**, — сбойный
   handshake: сетевой обрыв и обычный реконнект по backoff (иначе браузерный таймаут держал бы
   «подключение» минутами). Реконнект — 1 с × 2ⁿ с потолком **5 с** при видимой вкладке и живой
   сети и **60 с** в фоне/offline (не будим устройство зря). Ожидание прерывается `online`/
   `visibilitychange`/`pageshow`. Причины обрыва: `network | heartbeat | restart | manual | auth`
   (WS close `1008` → `auth`). Слушатели `online`/`offline`/`visibilitychange` снимаются в
   `import.meta.hot.dispose` (dev-гигиена: при HMR не дублируются).
5. **Индикация — один баннер, без модалок.** `ConnectionStatus` (заменил `ConnectionGuard`)
   монтируется **вне** `AuthGate`; при **любой не-`online` фазе** (включая залипший первичный
   `connecting`) дольше **15 с** показывает верхний баннер: «Нет связи с сервером / Восстанавливаем
   соединение…» + «Повторить» (`restart()`) + «Обновить страницу» (`reload()`). Баннер исчезает сам
   при `online`. `versionMismatch` **не** считается потерей связи: баннер подавляется — там уже есть
   error-тост о несовместимой модели сообщений, и «нет связи» вводило бы в заблуждение. Гибридная
   индикация **взаимоисключающая**: при `phase !== 'online'` inline `HybridOfflineBanner` скрыт
   (показывается полоса `ConnectionStatus` с «Повторить»/«Обновить страницу»), а при
   `phase === 'online'` и гибридном offline — наоборот, виден `HybridOfflineBanner` (удалённый
   backend недоступен, локальные данные работают). Раз в 15 с, пока баннер виден, — один probe `GET /auth/status`:
   если сервер ответил `authenticated: false`, это **реальное истечение сессии** (тост
   `connection.sessionExpired` + переход в `guest`); сетевая ошибка/таймаут ничего не меняют.
6. **Политика уведомлений: о связи не уведомляем.** Тостов «связь потеряна/восстановлена» и
   модальных confirm больше нет (ключи `connection.lost/offline/reload*` удалены) — состояние связи
   показывается только баннером и индикатором в шапке. `ToastContainer` получил
   `pauseOnFocusLoss={false}`: без этого таймеры тостов «залипали» после переключения приложения.
7. **Прочее.** Транспорт стартует по `authPhase === 'authenticated'`, а не по наличию профиля (ошибка
   `GET /auth/profile` больше не блокирует подключение; один повтор). `GlobalTransportIndicator`:
   клик — переподключение, Shift+клик — смена режима, цвет — по `phase`. `PwaUpdatePrompt` не
   перезагружает страницу при `checking`/`unreachable`/не-`online` (авто-reload разрешён только при
   `guest` или `authenticated` + `online`), не проверяет версию при `document.hidden`, а отложенное
   обновление пересчитывается при смене `phase`/`authPhase` — применяется сразу при восстановлении
   связи, без ожидания 30-минутного интервала.

## Что осознанно не делаем

- **Тосты о потере/восстановлении связи.** Шум при возврате из фона; состояние видно в баннере и
  индикаторе, а действие (переподключение) доступно одной кнопкой.
- **Модальный confirm «Обновить страницу?».** Модалка перекрывает интерфейс и «залипает» после
  восстановления; reload — необязательное действие в баннере.
- **Watchdog для SSE.** У `EventSource` нет `pong`; детект — только `onerror` и idle-таймаут
  `resume()` (90 с), по которому транспорт пересоздаётся при возврате вкладки/сети.
- **Изменение формы входа при реальном истечении сессии.** Реальный `authenticated: false`
  по-прежнему ведёт в `guest` с прежней формой (в т.ч. OIDC-веткой) — это не «связь», а вход.
- **Ретраи HTTP-запросов «вслепую».** Дедлайн обрывает только чтения; повтор — на уровне
  вызывающего или пользователя, без скрытых очередей. Мутации без явного `timeoutMs` не обрываются
  таймером вовсе.

## Альтернативы

- **Оставить булев `connected` и добавить флаг «потеря связи».** Отклонено: два конкурирующих
  признака в одном сторе дают расхождения (что показывает шапка, что баннер, что `PwaUpdatePrompt`).
  Фаза — одно поле, из которого выводятся все индикаторы.
- **Считать любую ошибку `GET /auth/status` гостем** (как было). Отклонено: на managed/OIDC это
  показывает неверную ветку формы и визуально разлогинивает при сетевом сбое.
- **Показывать баннер сразу при обрыве.** Отклонено: короткие обрывы (переключение сети, сон
  вкладки) восстанавливаются за секунды — баннер «мигал» бы; порог 15 с оставляет только реальные
  разрывы.
- **Один потолок backoff (5 с) всегда.** Отклонено: в фоне/offline это будит радио и жжёт батарею;
  потолок 60 с останавливает шторм попыток, а `online`/`visibilitychange` возвращают быстрый режим.

## Последствия и риски

- **Хорошо:** недоступный сервер больше не выглядит разлогином; «зомби»-сокет детектится за 30 с,
  зависший handshake — за 10 с; восстановление незаметно (реконнект ≤ 5 с на экране); пользователь
  видит одно состояние связи и два действия; реальное истечение сессии отличается от сетевого сбоя;
  долгие мутации (бэкап, миграции, установка плагина, консолидация) не обрываются дефолтным
  таймаутом.
- **Гибрид:** индикация взаимоисключающая — при `phase !== 'online'` виден только `ConnectionStatus`
  (кнопки «Повторить»/«Обновить страницу»), а `HybridOfflineBanner` скрыт; при `phase === 'online'` и
  гибридном offline виден `HybridOfflineBanner` (удалённый backend недоступен, локальные данные
  работают). Двух полос одновременно нет.
- **Риск — «залипший» `unreachable`:** если сеть есть, а сервер отвечает ошибкой не-сетевым
  исключением, гейт остаётся на экране «Сервер недоступен» с backoff (2,5…30 с, индекс сбрасывается
  только успехом); выход — «Повторить» или перезагрузка (баннер/экран), автоповтор продолжается.
- **Риск — ложное «нет связи» при несовместимости:** поэтому баннер подавляется при
  `versionMismatch` — несовместимая модель сообщений показывается отдельным error-тостом, а не
  «баннером связи».
- **Риск — зависшая мутация:** раз дефолтного таймаута у `POST`/`PUT`/`PATCH`/`DELETE` нет, зависший
  запрос не оборвётся сам; отмена — внешним `signal` (где он есть у вызывающего) или уходом со
  страницы.
- **Риск — локальные подсказки `navigator.onLine`:** браузер может считать сеть живой при мёртвом
  шлюзе; поэтому потолок backoff выбирается по «видимо и online», а живость соединения определяет
  watchdog/ошибки, а не только флаг.
- **Риск — probe-запрос раз в 15 с:** один лёгкий `GET /auth/status`, только пока баннер виден и
  только при `authenticated`; при недоступном сервере он падает по 8-секундному дедлайну и ничего не
  меняет.
- **Совместимость:** `connected` и ключи `transport.*` сохранены; удалены только ключи
  `connection.lost/offline/reload*` (тостов больше нет), новых каналов транспорта нет (ADR-024).

## As-built (2026-11-08): offline-деградация удалённой стороны гибрида

Инцидент: после пробуждения ноутбука удалённый backend недоступен, но локальный core отвечал
«локальным миром» без признака деградации — UI показывал пустой список сессий («все пропали»), а
офлайн определялся только по `/hybrid/status` с задержкой.

- **Признак в ответе.** `GET /api/v2/sessions` и `GET /api/v2/projects` в catch-ветке `RemoteError`
  добавляют аддитивное `remote_offline: true` (в обычных ответах поля нет); контракт пагинации не
  меняется (ADR-118 §4, docs/API_V2.md §«Пагинация списков»).
- **`hybridStore.remoteDegraded`** ставится при `remote_offline` из списков сессий/проектов и
  снимается успешным `loadStatus` с `connected === true`. `selectIsOffline` = `enabled && !connected`
  **или** `remoteDegraded` — баннер появляется сразу, не дожидаясь опроса статуса.
- **`stale` в `sessionsStore`/`projectsStore`**: при `remote_offline` ранее загруженные `remote:`
  записи **не затираются**, список помечается `stale: true`; `HybridOfflineBanner` при `stale`
  добавляет строку `hybrid.staleList` («Показаны данные до потери связи»). Взаимоисключение с
  `ConnectionStatus` (только при `phase === 'online'`) сохранено.
- **Форма входа.** Транспортные ошибки несли `fetch failed`/`The operation was aborted due to
  timeout` без причины: `describeTransportError` теперь распознаёт `TimeoutError`/`AbortError`
  (`: timeout — сервер не ответил за 15 с`), OIDC-дискавери и `postFormDetailed` передают в него
  `timeoutMs`. `/auth`-клиент прикрепляет к `Error` `status` и `code`; `authStore.errorCode ===
  'OFFLINE'` даёт отдельный блок «Сервер недоступен» с подсказкой и кнопкой повтора, а 401 —
  прежний блок «неверный пароль».
- **Тесты:** `remote/transport-error.test.ts` (таймаут с/без `timeoutMs`, `cause`),
  `remote/device-flow.test.ts` (текст причины), `server/routes/hybrid.test.ts` (`remote_offline`
  и его отсутствие), UI — `stores/{hybridStore,sessionsStore,authStore}.test.ts`,
  `components/layout/HybridOfflineBanner.test.tsx`, `components/auth/LoginForm.test.tsx`.
