# ADR-142: Перенос сессии между проектами — блокеры, согласие и эффекты

> **Статус:** ✅ Реализовано
> **Дата:** 2026-11-17
> **Источник:** PROP-141 (принято; файл удалён).
> **Связано:** [ADR-040](./adr-040-sessions-without-project.md) (перенос сессии), [ADR-111](./adr-111-background-subagent-sessions.md)/[ADR-113](./adr-113-background-processes.md) (фоновые прогоны), [ADR-114](./adr-114-git-worktrees.md) (worktrees), [ADR-132](./adr-132-ui-terminal.md) (терминалы), [ADR-051](./adr-051-scheduler-pipelines.md), [ADR-141](./adr-141-timers-alarms.md), [ADR-118](./adr-118-message-stream-v2.md).

## Контекст

Перенос сессии (`PATCH /sessions/:id {project_id}`, ADR-040) менял только `projectId`, `planApproved` и снимал worktree — молча. Живые ресурсы оставались привязаны к старому проекту: фоновые процессы исполнялись в старом workspace, записи прогонов и терминалов хранили старый `projectId`, дочерние сессии саб-агентов оставались в старом проекте, а новые автоматизации (ADR-141) продолжили бы срабатывать в сессию нового проекта. Участники нового проекта получали доступ к логам и терминалам старого workspace.

## Решение

1. **Единый шов** `SessionMoveService.move` (`packages/core/src/sessions/move-service.ts`): HTTP `PATCH`, `project_attach`/`project_create` и импорт/merge вызывают только его; проверок в обработчиках нет (инвариант 16).
2. **Блокеры:** активный ход; `running` фоновые процессы/саб-агенты; `running`/`starting` терминалы; активные таймеры/будильники; включённые расписания с целью `bound`/`queue`; worktree.
3. **Без согласия** — `409 SESSION_HAS_ATTACHED_STATE` + `details` (counts + `{id,kind,name}`). С `move_consent:{stop_running,cancel_automations}` — детерминированный порядок: stop processes → stop subagents → close terminals → cancel automations → detach worktree → перенос поддерева → смена `projectId` → переатрибуция завершённой истории. Неудача останова → перенос **не выполняется** (fail-closed).
4. **Поддерево:** все потомки переносимой сессии (включая завершённые) с прежним `projectId` переезжают вместе с родителем; их worktree снимается.
5. **Переатрибуция:** записи фоновых прогонов получают новый `projectId`; закрытые терминалы остаются в старом проекте (безопасного переноса нет) — факт фиксируется в `effects`.
6. **Согласие — только человек:** `project_attach`/`project_create` при блокерах возвращают ошибку с подсказкой; `service-key` с `move_consent` → 403; `remote:`-сессия → 409.
7. **Уведомление:** после переноса в корневую сессию пишется служебное `session_moved` (эффекты, from/to, поддерево) **без запуска хода**; `session.moved` несёт `effects[]`; аудит `scope:'session'`, `action:'move'`.

## Альтернативы

- **Переносить всё за собой** — отклонено: `cwd` живого процесса/PTY не меняется, доступ к старому workspace остаётся; владелец автоматизации может не быть участником нового проекта.
- **Молча отменять автоматизации** — отклонено: скрытая потеря работы.
- **Разрешить агенту согласие** — отклонено: согласие даёт человек через UI.

## Последствия

- Перенос — «тяжёлая» операция: один диалог со списком последствий.
- История следует за сессией: отчёты по проектам меняются осознанно.
- Старый проект теряет перенесённое поддерево из обзора.
