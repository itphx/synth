# AD-080: Управляемый гибрид: режимы-полюса, идентичность и установка локально

> **Статус:** 🧩 Предложение — Управляемый гибрид: режимы-полюса при запуске, standalone=ADMIN / hybrid=роли сервера
> **Решение до:** 2026-11-14
> **Дата:** 2026-09-29
> **Источник:** согласовано 2026-09-29
> **Сужает:** [AD-045](./ad-045-hybrid-server-profiles.md) (runtime-смена режима и адреса убирается)

**Решение:** `standalone` и `hybrid` — два **полюса**, а не режимы одного переключателя. Режим определяется **при запуске процесса** и не меняется в рантайме:

- `standalone` (по умолчанию) — локальная личность, локальный API-key → **ADMIN**;
- `hybrid` (запуск с `--connect`/`remote.enabled`) — личность и роли **строго с сервера**, локальный API-key прав не даёт.

Простого «переключения по кнопке» нет: чтобы сменить режим, процесс **перезапускается**. Локальные наработки при этом сохраняются: home/dataDir один и тот же (AD-079), поэтому локальные сессии, созданные в standalone, **видны в гибридном запуске** рядом с серверными.

## Контекст

- AD-045 сделал вход «лёгким runtime»: standalone-процесс мог в UI ввести адрес и логин и **на лету** стать гибридом (`POST /auth/login` → `connectRemote` в `packages/core/src/server/routes/auth.ts`). Смена сервера — тоже runtime.
- Проблема в идентичности: в standalone пользователь всегда ADMIN (локальный ключ), а в гибриде его роль определяет сервер. Runtime-переход между полюсами смешивает модели прав и снижает осознанность («где я сейчас и от чьего имени действую»).
- Авто-подключение к `lastProfile` по умолчанию (`packages/synth/src/cli.ts`) делает запуск неявно-гибридным даже без намерения пользователя (исходный баг standalone, см. AD-079).
- `remote.worlds: {local, remote}` объявлена в конфиге, но **не читается** — видимость миров не управляется.

## Решение

### Режим — параметр запуска

- `standalone` — без `--connect` и без `remote.enabled`; локальный API-key → ADMIN.
- `hybrid` — `--connect <url>` (или `remote.enabled` в config.yaml); личность с сервера.
- Авто-подключение к `lastProfile` по умолчанию **убирается**: адрес задаётся явно (`--connect`/`--profile <url>`/конфиг).
- **Адрес сервера меняется только перезапуском** (runtime-смена адреса внутри гибрида, из AD-045, снимается).
- `logout` остаётся (забыть токен + revoke). Идея «отключиться, оставив сервер» (без рестарта) **не вводится** — она была следствием runtime-переключения.

### Идентичность

- `standalone`: единственная личность — локальный API-key (ADMIN). Гибридного входа нет: `/auth/login` в этом режиме недоступен, поля «Сервер» в форме входа нет.
- `hybrid`: единственная личность — серверная (cookie после логина логин/пароль или сохранённые credentials). Роли — из claims сервера. **Локальный API-key в гибриде прав не даёт** (не является источником личности; для автоматизации — только серверные credentials).
- Форма входа hybrid содержит логин/пароль (адрес — из запуска), поле адреса не редактируется.

### Видимость миров и индикация

- `remote.worlds` оживляется как фильтр видимости (локальные/серверные/оба).
- В UI — постоянный индикатор режима (помимо `origin`-бейджей сущностей), чтобы пользователь всегда видел, в каком полюсе работает.

### Установка локально (onboarding гибрида)

- В managed-UI (роль, которой доступен раздел) в панели профиля — пункт **«Установить локально»**: инструкции по установке гибрида с **заранее прописанными параметрами подключения** (сервер; issuer/cli-client core узнаёт через `GET /auth/oidc-meta`, AD-043).
- Первая итерация — **Linux**; macOS/Windows — позже.

## Что сохраняется из AD-042/AD-045

- Агрегация миров (`origin`, `remote:<id>`), проксирование, RemoteEventBridge, LLM Proxy, publish/fork (политики — AD-081).
- Единый `dataDir` инстанса: локальные сессии переживают смену режима (через перезапуск, тот же home).
- `credentials.json` и реестр `profiles.json` — как хранилища (пути — home-относительные, AD-079); авто-подключение по профилю больше не выполняется.

## Последствия

- Нет скрытого смешивания личностей: ADMIN-standalone не «протекает» в гибрид.
- Запуск предсказуем: без `--connect` процесс всегда standalone.
- Смена режима — осознанное действие (перезапуск), локальные данные не теряются.
- Меньше runtime-магии: `--no-auto-profile` теряет смысл (авто-профиль убран).

## Ограничения

- Смена режима требует перезапуска — осознанный компромисс UX ради разделения полномочий.
- Требуется доработка UI/сервера: убрать смену адреса и hybrid-вход из standalone-ветки, ввести индикатор режима.
- `standalone` в managed-окружении сохранён как полюс, но его политики/данные — вне центрального контроля (см. AD-081 и AD-073).
