## 0.13.10 (2026-11-18)

**Cumulative release of two waves — 0.13.9 and 0.13.10: notes for the whole v0.13.8..HEAD range
(258 commits, 1,267 files, +199,006 / −14,809 lines), not a single patch delta.**
Version 0.13.9 was never published to npm: it shipped only to test (images `0.13.9`, charts
`0.13.9-25/27/32`) and as betas to the Gitea npm registry, so this document describes both waves.
0.13.10 is the current version of all eight published packages and of the `synth` chart;
`packages/provisioner` stays private (`private: true`, version `0.13.9`) and is not part of the npm
ship.

The headline of 0.13.10 is that execution stopped being a mode and became a **contour**: `remote` is
brought up to the full set of file, search, git and shell tools, pools, a profile catalog, a separate
provisioner, a sandbox and a built-in browser have appeared, and isolation (non-root, read-only,
network classes) became a contract instead of a recommendation. Alongside grew three things the
contour cannot live without: a terminal with a PTY on the executor, project access as a single axis
(members, groups, ownership transfer) and automation without `sleep` — timers and alarms. The second
half of the release is about honest state: point writes of a session instead of a full rewrite,
durable stop reasons, auto-detach of background work, content filtering of tool output and an LLM
gateway that is on by default.

### Release focus

- **Execution is a contour, not a mode** ([ADR-135](../arch_decisions/adr-135-execution-contour.md),
  [ADR-136](../arch_decisions/adr-136-shell-trust.md),
  [ADR-137](../arch_decisions/adr-137-executor-isolation.md),

  process, `sandbox_exec`, built-in `browser_*` and `ctx.runtime` for plugins. Isolation — non-root,

- **A terminal in the product** ([ADR-132](../arch_decisions/adr-132-ui-terminal.md)): a PTY at the
  execution point, an xterm.js tab, eight `terminal_*` tools, output snapshots restored after a
  restart, the “Ask the agent” dock and a tier 6 image (zsh + Oh My Zsh + tmux).
- **Collaboration** ([ADR-140](../arch_decisions/adr-140-project-access-sharing.md)): one access axis
  (`members` + `groupMembers` + `everyoneRole`, `visibility` is derived), a single
  `resolveProjectAccess` resolver, groups from OIDC, user and group directories, ownership transfer
  and recomputation of WS/SSE subscriptions when access changes.
- **Automation without `sleep`** ([ADR-141](../arch_decisions/adr-141-timers-alarms.md)): the `Timer`
  entity (`timer`/`alarm`) with `steer` delivery, project schedules with a mandatory `projectId`, the

- **Honest stops and background work** (PROP-142, PROP-143,
  [ADR-145](../arch_decisions/adr-145-background-timeout-output-detach.md)): a durable
  `execution_stopped` record instead of `role:'error'`, subagent auto-recovery with a budget and a
  crash loop, blocking runs in the API and the UI, auto-detach on steer/interrupt, a live log from
  the first second.
- **Write reliability and security by default**
  ([ADR-144](../arch_decisions/adr-144-atomic-session-writes.md),
  [ADR-146](../arch_decisions/adr-146-tool-content-filtering.md),
  [ADR-147](../arch_decisions/adr-147-llm-gateway-default-on.md)): point session mutations with a

- **Input and reading**
  ([ADR-126](../arch_decisions/adr-126-input-surface-commands-mentions-snippets.md)): `/compact`,
  `/review`, `$`-skills, `#`-snippets, `@`-mentions and `!name` project scripts; plus markdown

### Execution contour: full `remote`, pools, profiles and provisioner (ADR-135…138)

- **`execution.mode=remote` became complete.** **All** file, search, git and shell tools run on the
  executor: `read_file`, `list_directory`, `write_file`, `edit_file`, `delete_file`,
  `create_directory`, `patch`, `attach_workspace_file`, `save_attachment`, `send_attachment`, `glob`,
  `grep_files`, `git_*`, `execute_shell`. The control plane no longer reads the agent's FS — this is
  recorded as an invariant in the root `AGENTS.md`.
- **The execution port is extended to `exec + fs + stream`:**
  `fs.realpath/stat/readdir/readText/sniff/readBytes/writeFile` (atomic tmp→rename),
  `/edit/mkdir/remove/rename/hash` and a binary `stream` (download/upload; base64 only for small
  files). The `features.fs` flag in `GET /capabilities`; `remote` without `features.fs` fails closed
  (`ExecutionFsUnavailableError`).
- **Pools and classes:** `execution.remote.pooling = instance|project|session`, the canonical pool
  key `scope:id:class:profile`, classes `exec | browser | sandbox`. The browser pool is **always**
  per-project (`project:<id>:browser:<profile>`), so cookies do not leak between projects.
- **Profile catalog:** `execution.remote.profiles` (`url`/`timeoutMs`/`concurrency`/`failMode` +
  metadata `description`/`image`/`network`/`resources`/`runtimeClass`/`mcpServers`/`class`/
  `placement`), `defaultProfile`, `fallback = instance|fail`, `disabledProfiles`. Binding:
  `session.settings.executorProfile` → `agent.executorProfile` → `project.executor.profile` →
  `defaultProfile`, with the ceilings `project.executor.allowedProfiles` ∩ `agent.allowedProfiles`
  (an explicitly empty list = no profiles, fail-closed).
- **The provisioner is a separate process, not a K8s client inside the backend:** the private
  package `@itphx/synth-provisioner` with the contract `POST /v1/pools`,
  `POST /v1/pools/{key}/touch|drain`, `DELETE /v1/pools/{key}`, `GET /v1/capabilities`,
  `GET /v1/profiles`, `GET /health`, `GET /metrics`. Providers: `static` (addresses from the config)
  and `kubernetes` (a Pod + Secret per pool key, adopt by the labels `synth.io/pool-*`, the reaper
  is a single writer). Lifecycle: `startTimeoutMs` 120 s, project idle 900 s, session 300 s,
  `maxLifetimeMs` 12 h, `drainGraceMs` 30 s, `maxPools` 50 → `429`.
- **`sandbox_exec`** — a one-shot run of 1…5 commands in a pool of the `sandbox` class
  (`session:<id>:sandbox:<profile>`), with the same audit and external checker as `execute_shell`;
  an inline fallback is forbidden.
- **Built-in `browser_*` instead of MCP discovery:** `browser_navigate`, `browser_snapshot`,
  `browser_close`, `browser_click`, `browser_type`, `browser_press`, `browser_wait`,
  `browser_screenshot` (capability `web`) call `ExecutionPort.browserCall` → `POST /mcp/call` into
  the project browser pool. The browser MCP server stays connected, but its tools are **not
  registered** (`hiddenServers`), so `playwright_*` no longer duplicates `browser_*`. A screenshot
  arrives as a message attachment (`ToolResult.attachments`); when there are none, the file
  `…/.playwright-mcp/*.png` is read through the pool's FS.
- **A separate browser profile contour:** `browserProfiles`, `browserProfile`,
  `allowedBrowserProfiles`, `session.settings.browserProfile`; browser profile names are excluded
  from the exec catalog.
- **Runtime profile catalog** (backend-owned, `ADMIN` only):
  `GET/PUT/DELETE /api/v2/settings/execution` (merge: config + runtime − `disabledProfiles`;
  `profileOrigins`, `restartRequired`), the admin API `GET /api/v2/execution/profiles` (+ `details`,
  `browserProfiles`, `browserDefaultProfile`), `GET /api/v2/execution/pools`,
  `POST /api/v2/execution/pools/:key/drain`, `DELETE …/pools/:key`,
  `POST /api/v2/execution/images/warm` (DaemonSet warm-up, `kubernetes` only).
- **`workspaceSubPath`:** the project directory is mounted into the pod (for a worktree —
  `.worktrees/<projectId>`), not the whole RWX volume. Plugins received `ctx.runtime` (`exec` without
  a shell + `fs`) for inline tools and out-of-process over protocol v2 (a loopback proxy
  `SYNTH_RUNTIME_URL` + `SYNTH_RUNTIME_TOKEN`, invocation binding); the runtime is issued only to a
  tool with the file/shell capability.
- **Execution metadata in the prompt:**
  `prompts/system/ENVIRONMENT.{inline,remote-instance,remote-project}.{ru,en}.md`; profiles of the
  built-in agents: `leader` — `default/devops`, `researcher`/`explore`/`security-auditor` — `light`,
  `devops`/`admin` — `devops`, `title` — no profiles; `executor_profile`/`allowed_profiles` in the
  agents admin API and in the “Agents” form.
- **Infrastructure:** `docker/Dockerfile.provisioner`, `docker/executor-init.sh`, the chart —
  `provisioner-deployment.yaml`, `provisioner-rbac.yaml`, `provisioner-service.yaml`,
  `provisioner-networkpolicy.yaml`, `serviceaccount.yaml`, `executor-network-classes.yaml`; values
  `provisioner.*`, `executor.networkClass(es).*`, `provisioner.kubernetes.fsGroup` (for NFS —
  `null`).

### Built-in terminal (ADR-132)

- **PTY at the execution point:** `ExecutionPort.openPty`/`PtyHandle`, the provider
  `@homebridge/node-pty-prebuilt-multiarch` (lazy `import()`), routes `/pty/*` (NDJSON stream),
  `features.pty`; without a PTY — an honest `EPTY` refusal.
- **Ownership is project-level, the session link is optional:** cwd — the session worktree, otherwise
  `project.workspace`. Limits `terminal.maxPerProject` (default 8, range 1…64) and
  `terminal.maxPerInstance` (default 32, 1…256), idle `terminal.idleMinutes` (30…10080, default
  2880 = 2 days), pool heartbeat every 5 minutes.
- **Snapshots and restore:** `terminals/<id>/meta.json` + `output.txt` in `BlobStore`;
  `runningAtSave` distinguishes live terminals from finished ones; `terminal.autoRestore` (default
  `true`); `POST /terminals/:id/restart` brings up a new PTY **keeping the output history**; a
  finished terminal answers `409 TERMINAL_EXITED`.
- **API** (`docs/API_V2.md` §5.43–5.44): `GET/POST /api/v2/terminals`, `GET/PATCH/DELETE /:id`,
  `GET /:id/output?since=`, `GET /:id/foreground`, `GET /:id/stream` (NDJSON, heartbeat 15 s),
  `POST /:id/input|resize|restart`; a frame of 16 KiB → `413 TERMINAL_LIMIT`, > 20 frames/s → `429`.
  Settings — `GET/PUT/DELETE /api/v2/settings/terminal` (`sources`, `defaults`, `envLockedFields`,
  `409 ENV_LOCKED`).
- **Agent tools** (the `terminal` capability, separate from `shell`): `terminal_list`, `terminal_open`,
  `terminal_read`, `terminal_snapshot`, `terminal_write`, `terminal_signal`, `terminal_close`,
  `terminal_run` (`{background}`). In plan mode writing is forbidden; `terminal_write {enter:true}`
  passes `checkShellCommand`; a full audit (`terminal.input` for frames with Enter), everything else
  is a metric.
- **Command launch mechanics:** a text marker `@@srn-<nonce>:<code>@@` (OSC does not get through
  tmux), the command + marker in **one frame**, CR instead of LF for Enter, `strip_ansi`, `delay_ms`
  (0…2000), `kill_on_timeout` (INT on timeout), `still_running` instead of killing, the refusal
  `TERMINAL_FOREGROUND_APP` in full-screen applications, `TERMINAL_FOREGROUND_BUSY` when the terminal
  is busy. Foreground classification — by `/proc/<pid>/stat` (protocol 9,
  `GET /pty/:id/foreground`); `ssh`/`mosh`/`docker`/`kubectl` are allowed without path checks
  (someone else's machine).
- **UI:** the `terminal` tab of the center area (xterm.js 6), a tab-session with a switcher, terminal
  cards and a section in “Processes”, the “Ask the agent” dock (`POST /prompt` with a separate
  `context` field, 32 KiB cap), “Attach output” in the `terminal_read` format, theme and font from
  `preferences.terminal` (theme `synth`, a bundled Symbols Nerd Font Mono 363 KiB), inline rename,
  middle click (shell → close, busy → toast), the admin sections “Terminals” and “Execution
  parameters”.
- **Image:** tier 6 (`docker/install-tier-6.sh`) — zsh + Oh My Zsh (pinned by commit) + tmux ≥ 3.3 +
  `ncurses-term`, `/etc/synth/{zshrc,tmux.conf}`, `executor-init.sh`; the PTY is built from source in
  Alpine flavors; the `browser` flavor — without a PTY.
- **Settings:** `terminal.enabled=false` → `403 TERMINALS_DISABLED`, live terminals are closed, the
  `terminal` capability disappears from the prompt; priority env > runtime > config > default.

### Project access: members, groups, ownership transfer (ADR-140)

- **One access axis instead of an enum:** `members` + `groupMembers` + `everyoneRole`; `visibility`
  (`author|selected|all`) is **derived** (`deriveProjectVisibility`) and is forbidden in the request
  body (`400`).
- **A single resolver** `resolveProjectAccess` (`@itphx/synth-shared`, browser-safe): owner →
  `ADMIN`/`LEAD` → `members` → the highest role across groups → `everyoneRole` → no access (an
  unknown role is treated as `viewer`, fail-closed). Every former copy of the predicate was migrated
  to it: backend RBAC, session visibility, tools, `list(viewer)` in file/memory/PG, the UI mirror and
  the ADR-106 turn ceiling.
- **Rights:** visibility grants **read only** (`viewer` is read-only, no turn is started); access can
  be changed by `canManage` (the author, `OWNER`, `LEAD`, `ADMIN`); `ADMIN`/`LEAD` see everything;
  the author is always `owner` in `members`, a demotion is `400`.
- **Group source:** `auth.oidc.groups { claim?, allow[] }`, env
  `SYNTH_OIDC_GROUPS_CLAIM`/`SYNTH_OIDC_GROUPS_ALLOW` (csv; the allowlist is case-sensitive, an empty
  allowlist = no groups, fail-closed), claim fallback `id_token → access_token`; `User.groups` is a
  **snapshot at login**; in hybrid — `RemoteUser.groups` → cookie v2 → `credentials.json`.
- **Directories:** `GET /api/v2/users/directory` (a light projection, ACL ids) and
  `GET /api/v2/users/groups` (names from the allowlist, `?q=`, paginated) — available to any
  authenticated user; the `/users/groups` route is declared before `/:id`.
- **Synchronization:** an access change publishes `project.updated {kind:'access'}`,
  `EventHub.resyncAllClients()` recomputes WS/SSE subscriptions (a new member receives events, a
  revoked one stops), the UI re-reads project and session lists.
- **Ownership transfer:** `POST /api/v2/projects/:id/transfer {user_id}` (a strict `.strict()`
  schema); the right belongs to the current owner or `ADMIN` (not `LEAD` and not an `OWNER` member);
  the new owner → `owner`, the former one → `editor`; atomically through `store.mutate`; audit
  `scope:'projects'` with `owner_id`; codes `404/403/400` (`service:*`, self, unknown/inactive,
  `remote:`).
- **ACL ids:** `GET /users/directory` returns ids in the `User.id` space (identity `provider:'auth'`,
  `externalId`), not `profile.id`; the link is created at login (idempotent, best-effort). Legacy
  profiles without a link — `profile.id`.
- **Transfer policy:** a portable archive **does not contain** `members`/`group_members`/
  `everyone_role`/`visibility`; import (including `--merge-into`) → “author only”;
  `syncProjectToRemote` does not carry grants; `forkProjectToLocal` → “author only”, the owner is
  `local`.
- **Automations are project content** (addendum 2026-11-17): reading — any member, mutations —
  `EDITOR`/`OWNER`.

### Automation: timers and alarms (ADR-141)

- **A new `Timer` entity** (`timer | alarm`), not an extension of `Schedule`: `comment` (1…500) is
  the only meaning of a firing and **it has no prompt of its own**; `projectId` and `sessionId` are
  mandatory — instance-level automations do not exist. Alarm ids are `alm_`.
- **Recurrence:** `once`, `daily HH:MM` (IANA time zone), `every N` (10…2,592,000 s); the one-shot
  horizon is 30 days; the limit is 50 active timers per session, the minimum interval 10 s.
- **The `TimerService` engine** (`engine/timers/`): a port + file/memory/PG (migration `037`), a
  single `setTimeout` + a safety tick every 30 s (accuracy ~1 s), the `SharedLeader` shared with the
  scheduler, catch-up of an overdue one-shot, dedup by `(timerId, scheduledFor)`, metrics.
- **Delivery:** the event `{source:'timer', type:'timer_fired'}` through `EventIngress`/the Router →
  the `bound` decision + `delivery:'steer'` → `createBackgroundParentNotifier` (steer into the
  current turn → queue → fallback); the service message `timer_fired` (`role:'user'`,
  `author:'Timer'`, the envelope `<timer …>`), live events `timer.*`.
- **API** (`docs/API_V2.md` §5.45): `GET/POST /api/v2/timers`, `PATCH /:id`, `POST /:id/stop`,
  `POST /:id/pause`, `DELETE`; scopes `timers:read|write` for service keys; the project is derived
  from `sessionId`.
- **Tools:** `timer` (`create|list|update|stop|delete|show`) and `alarm`, capability `schedule`;
  strict schemas (extra arguments are an error), `allow_duplicate` (default `false`; a duplicate →
  `409 TIMER_DUPLICATE` + `details.existingId`), `at` in the past is an error with a 60 s tolerance,
  `update` on `fired`/`cancelled` is refused, `stop` is idempotent for terminal states,
  `list status=…` to find finished ones. The `cancel` verb was replaced by `stop`/`delete`.
- **Schedules became project-level:** `projectId` is mandatory (migration `038`, backfill), legacy
  schedules without a project are disabled with `lastError='project_required'`; `GET /schedules` is
  scoped by projects, mutations — by project role, service keys — by `allowedProjects`.
- **UI:** the “Automation” panel (schedule/timer/alarm sections, the “session → project” scope,
  filters, counters, a unified card, modals, history), the `time`/`alarm` badges in the session tree.
- **The SDK is deliberately not extended** with timers — HTTP API only (the owner's decision).

### Moving a session between projects (ADR-142)

- **A single seam `SessionMoveService.move`** (`sessions/move-service.ts`): HTTP `PATCH /sessions/:id`,
  `project_attach`/`project_create`, import and merge go only through it; there are no checks in the
  handlers.
- **Blockers:** an active turn, `running` background processes and subagents, `running|starting`
  terminals, active timers/alarms, enabled `bound|queue` schedules, a worktree. Without consent —
  **`409 SESSION_HAS_ATTACHED_STATE`** + `details` (counts and `{id,kind,name}`).
- **The `move_consent:{stop_running,cancel_automations}` consent** can only be given by a human; a
  `service-key` with `move_consent` → `403`; a `remote:` session → `409`.
- **A deterministic order of effects:** stop processes → stop subagents → close terminals → cancel
  automations → detach worktree → move the subtree → change `projectId` → re-attribute the finished
  history; a failed stop means the move is **not performed** (fail-closed).
- **The subtree** is moved entirely, including finished descendants; background run records get the
  new `projectId`; **closed terminals stay in the old project** (there is no safe transfer) — the
  fact is recorded in `effects`.
- **Notification:** the service message `session_moved` (effects, from/to, subtree) **without
  starting a turn**; the event `session.moved` with `effects[]`; audit `scope:'session'`,
  `action:'move'`.

### Tool timeouts — in seconds (ADR-143)

- **The `timeout` of every tool is in seconds** (an integer), milliseconds inside:
  `timeoutMs = timeout × 1000` at the boundary. Ports, `ExecRequest.timeoutMs` and config defaults
  (`git.*TimeoutMs`, `browserTimeoutMs`, `questions.timeoutMs`) stay in ms.
- **The limit depends on the mode:** foreground ≤ 600 s, background ≤ 86,400 s; `0` (“no limit”) was
  removed. Exceptions: `web_fetch` — a 600 s ceiling (default 30), `question` — 300…86,400 s.
- **The `.synth/scripts` declaration** — seconds 1…86,400 (a script is always background); no value
  = 86,400.
- **Executor:** `SYNTH_EXECUTOR_MAX_TIMEOUT_MS` = 86,400,000 (the default in Helm) instead of
  600,000; chart values are synchronized (the ADR-135 addendum of 2026-11-17).
- Labels, metadata and i18n — in seconds; tool descriptions recommend `timer` instead of `sleep`.
- **Breaking:** values > 86,400 are now a validation error; a background shell lives a day by default,
  so a long-lived dev server restarts itself.

### Session writes — point mutations only (ADR-144)

- **The `mwgvzwfc-33-2h30b0lt` incident:** a turn wrote tool results through `appendMessage`, while a
  parallel timer-steer delivery did `withLock` → load → `saveSession`; the snapshot overwrote someone
  else's write and `tool_use`/`tool_result` pairs broke.
- **The domain writes a session only through point operations of the `SessionRepository` port:**
  `mutateMeta`, `mutateHistory` (a fresh document under the lock, `seq` positional, `ord` not
  renumbered), `mutateMessage` (one message by `id`; `id`/`seq`/`createdAt`/`ord` are immutable),
  `appendMessage`/`updateMessage`, `shouldWrite` (“counted but not writing”), `touchUpdatedAt:false`.
- **A full write (`save`/`saveSession`/`updateSession`) — only for create/import/replace:**
  materialization, `forkSession`, importing an archive or a session, moving a project,
  `synth storage migrate`.
- **Atomicity:** FileStore and in-memory — a per-session `AsyncLock` in the process; PostgreSQL — a
  transaction + `pg_advisory_xact_lock` **before** reading.
- **The `session-write-census.test.ts` guard** scans `packages/core/src` and `packages/backend/src`
  and fails on a full write outside the allowlist (`sessions/manager.ts`, `projects/portable.ts`,
  `remote/transfer.ts`, `backend/src/routes/sessions.ts`, `maintenance/storage-migrate.ts`); it
  checks that the set of files is **exactly** equal to the allowlist, plus a detector self-check.
- **Stage 3c:** a “broken chain” is separated from an interruption — `recoverStreamingMessages` sets
  `disabled:true` + `metadata.repaired='orphan_tool_calls'`, a real `interrupted` is not set; the UI
  shows the neutral label “Step not sent to the model” (`chat.messageRepaired`).
- Invariant 2 of the root `AGENTS.md` was rewritten for this rule; the storage format did not change
  and there is no schema migration.

### Background work: `retime`, live log, blocking runs, auto-detach (ADR-145)

- **`retime` in the handle contract and executor protocol 10:**
  `ExecBackgroundProcess.retime?(timeoutMs)` (`0` — remove the timeout), the executor —
  `POST /exec/:id/timeout {timeoutMs}` (`0…86,400,000`; `404`/`400`), the flag
  `features.backgroundRetime`. Detach order: `retime(0)` **before** `adopt`; a refused `adopt` →
  the deadline is restored, the run stays foreground.
- **A live log from the first second:** `ProcessService.openLiveLog` →
  `processes/live/<processId>.log`; a foreground call tees at t=0, `adopt` **takes the same file**
  (no prefix copying); for `live/` — a separate pruning rule (an orphan only if there are no

### Subagents: steering a running one, auto-recovery, durable stops (PROP-142, PROP-143)

  regular user message with `metadata.continuation`, `model`/`provider` switch the pair (the catalog

  a child session is routed into the subagent loop (idle → resume with the text, busy → queue/steer),
  not into `QueueProcessor`.

  (`planBootRecovery`), the registry record continues (`status: running`, `metadata.resumed_from`,

### Tool content filtering and prompt injection (ADR-146)

- **IPI rules are a separate system block:** `prompts/system/CONTENT_RULES.{ru,en}.md`, the
  `content.rules` block in `SystemPromptComposer` (tier `stable`, order 12), the `contentRulesEnabled`
  gate = `security.promptInjection.enabled`; duplicates of `[CONTENT RULES]` were removed from eight
  roles; the loader is `getContentRules()` (`getRules` remains a `@deprecated` alias).
- **A single layer** `applyToolContentFilter` (`engine/security/tool-content.ts`) is applied by **all
  three cycles**: the main turn, the subagent loop (`task/run-cycle.ts`) and the pipeline agent step
  (`agent-step.ts`, `PipelineSecurityContentFilter`). Results with `isError` pass through the layer;
  system tools (`plan_*`, `todo_write`, `classify_conversation`) do not.
- **The trust matrix** `getToolTrust`: `trusted` — files inside the perimeter, git, project tools;
  `untrusted` — web, shell, `task`, `read_session_reference`, MCP, the terminal and plugins with
  `pluginTrust` below `trusted` (fail-closed); plugins are checked **before** MCP.
- **Marker escaping:** `escapeContentMarkers` — `[CONTENT`/`[/CONTENT]` → `\[…` (idempotent); a forgery
  **does not block** but is marked `injection_marker_escaped`; blocking comes only from the dictionary
  in `mode:block`. Addendum: the attributes of the opening marker are sanitized too
  (`wrapContentDetailed`, `sanitizeContentAttribute{Key,Value}`: removal of `]`/`|`, a cap of 120/40) —
  this closes defect D1 (P2), where `PATH`/`URL`/`QUERY` with `]\n[CONTENT END]` closed the block.
- **The terminal** returns raw text + `metadata`, the envelope is set by the shared layer (an attribute
  allowlist); service messages (the background notice, the terminal context) build the envelope
  themselves (`formatBackgroundContent`), `frameTerminalOutput` is a `@deprecated` alias.
- **MCP — an advisory scan:** on `registerTools` the dictionary detector walks `server.description`,
  `instructions`, `tool.description` and the name; a `[WARN]` line in the `mcp.servers` block, the
  metric `synth_content_filter_hits_total{source,kind}`, a log without the text; tools are not blocked,
  schemas are not mutated.
- **Setting:** runtime `security.promptInjection` (`enabled`, `mode`) in the UI “Security”, default
  `enabled: true`; priority env > runtime > config > default; env
  `SYNTH_SECURITY_PROMPT_INJECTION_{ENABLED,MODE}`; fixing a field by env → `409 ENV_LOCKED` with
  `fields[]`; live (`restartRequired: false`); `wrapContent` — `config.yaml` only.
- **Breaking:** result bodies change at the byte level (`[CONTENT` → `\[CONTENT`); a new block appeared
  in the prompt; terminal tools no longer set the envelope themselves — parse `metadata`.

### Known limitations and leftovers

- **Execution contour.** The remote builder for image builds is **documentation only**
  (`docs/EXECUTION.md` §10.2.1 and the chart README): the chart has neither `executor.extraEnv` nor a
  mount of a Secret with certificates — that is an infrastructure task. An e2e on the cluster (pods,
  RBAC, NetworkPolicy) was not run; gVisor and rootless buildah are opt-in and were not verified on a
  live cluster; the gateway-addons images are not brought to non-root.
- **The `mcp` pool class** (PROP-140) — a proposal: ready-made third-party MCP images are not
  connected. The default class of dynamic pools is `full` (fail-open, documented); `metricsIngress` is
  not applied with network classes enabled; the class selector is only the `synth.io/network` label, so
  within one namespace all pools of that class fall under the rules.
- **Plugins:** there is no SDK for `ctx.runtime`, the plugin runtime inside the executor is not done;
  `DEFAULT_BROWSER_MCP_SERVER` in `packages/executor/src/client.ts` is still `playwright` (the client
  fallback).
- **Terminal.** A hybrid PTY forward between instances is not supported; the `browser` flavor — without
  a PTY; tmux as a backend is not implemented (only a manual launch inside); a TUI inside `ssh` is not
  classified locally — `terminal_snapshot` helps; `terminal_run` is not yet described in the user
  portal.
- **Background and subagents.** Live handles are in process memory: multi-replica routing remains an
  open question (PROP-105), auto-resume in multi-replica must be disabled (currently fail-closed by
  ownership). Retention deletes both records and logs, including the live log of a detached run. Nested
  subagents — `deny`; a user question from a subagent — `deny`; there is no blocking join to a running
  run; recovery resumes the turn but **does not roll back** already executed tools (at-least-once);
  background processes are not resumed after a restart (only `orphaned`); there is no backfill of old
  child sessions — they stay monolithic. In an already open tab a finished step appears with the next
  `step.finished` (a one-step delay).
- **Automation.** Firing accuracy is approximate (tens of ms of drift under load); a delivery error is
  not retried automatically (`once` → `fired` with `lastError`, recurring ones — the next cycle); there
  are no timers in the SDK — deliberately.
- **Access.** A live check of the groups UI on an instance with Keycloak was not performed (in dev the
  group directory is empty); there are no notifications to added members; there is no mapping of IdP
  groups → `teamRoles`; there is no partial visibility — access opens all project content, including
  session history.
- **Storage and filtering.** FileStore is not protected across processes (coordination exists only in
  PostgreSQL); positional indices (the compression plan, `keepFrom`, checkpoints) do not survive an
  insertion at the beginning of the history. Binary attachments and built-in tool descriptions are not
  scanned; a pipeline step does not receive the flags of MCP server descriptions; the audit of a
  filtering setting change is only a log.
- **Gateway.** Observing `rate_limited` in standalone remains open; the limits 60/120 were not raised.
- **Interface.** Commit management (stage/unstage/commit/push, the message, the `scope:'git'` audit) is
  the next stage, it was not part of this wave; session worktree directories are not highlighted in

  `!important` kills `:focus-visible`; saving settings does not report the result) — **not fixed**, and

- **Documentation.** PROP-142/143 are implemented but remain proposals; `docs/EXECUTION.md`,
