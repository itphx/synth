## 0.10.0 (2026-10-14)

A major platform release: **external events and automation**, **schedules**, the **public API platform**
(service key + scopes, webhooks, OpenAPI, SDK), **decision models** and the **Telegram gateway** as a dedicated
class of extensions. 107 commits after v0.9.0.

### External events and automation (ADR-089)

- Core: `HookBus` (ADR-030, minimal slice) and the `Event`/`EventBinding`/`Router` entities; session
  creation is consolidated into the single funnel `RequestSessionService` (`direct` — an explicit request, `external_event` — via the Router).
- Routing rules `match → target` (`bound`/`queue`/`ephemeral`), `agentTemplate` resolution,
  the default mode (`bound`/`ephemeral`) and the Router decision journal.
- **Binding API keys**: a mandatory unique label, expiry and request rate limit, soft revocation,
  per-key and global rate limits, cascading deletion together with the binding.
- **auto-bind**: with `events.autoBind` the Router itself creates a binding for the chat/thread (shared chats,
  no manual setup).
- **Identity and visibility**: external identities are stored in the profile, a claim flow with a one-time
  code, an `identityMap` editor; the session owner is a person (not a chat), so messenger sessions
  are visible in the owner's UI; session/project lists account for the owner, project members and the cross-cutting ADMIN/LEAD view.
- **External sender permissions**: the baseline is the owner profile roles, gateway roles only **narrow** them
  (intersection), an unrecognized sender gets no permissions (fail-closed); effective roles are written
  into the message metadata for audit.
- Event journal retention (pruner), runtime settings of the "Events" section (master switch,
  ephemeral session TTL, sources, agent templates).
- UI: the user-facing "Events" section (bindings, keys with one-time secret display, journal),
  the admin "Event settings" section, the journal is mirrored in "Logs & Audit".

### Schedules (ADR-051)

- The `cron` source: the scheduler publishes `schedule_fired` via the Router and **does not create sessions itself**;
  schedule CRUD (`PUT` for updates), History, force run, catch-up.
- Scheduler messages come from the system user `Scheduler`, are shown in the UI as a centered
  Notice, and an explanatory volatile block `scheduler.turn` is added for the LLM.
- Multi-instance primitives (leader election, atomic dedup claim, cross-process locks, file-based
  implementations) are **off** by default.

### Public API platform (ADR-052, stages I–IV — closed)

- **Service keys** with `scopes` and the project projection `allowedProjects`: issue/revoke/limits, parity
  of RBAC and scopes in the core and the backend, the scopes catalog is served by the server (`GET /service-keys/scopes`).
- **Webhooks**: event subscriptions, an HMAC-SHA256 signature (`X-Synth-Signature`) with an acceptance window,
  retry/backoff with jitter, deduplication, an SSRF policy, a delivery journal, secret rotation/revocation.
- **public-OpenAPI**: the integration core and 28 operations on `@hono/zod-openapi`, named models,
  a unified error format.
- **SDK** `@itphx/synth-sdk` — a typed public API client (a new package in the monorepo).
- Delivery fix: session answers did not reach clients with a service key/elevated — watch-all mode
  was enabled for SSE/WS.
- The `addons:install` scope (+ `users:read`) and service key bootstrap — for installing add-ons.

### Decision models (ADR-084 — closed)

- The decision model class: the `decision` and `systemone` protocol providers, the micro cascade, decision classification
  for routing (including for external events).
- `primary → escalation` escalation, aggregate decision layer metrics (`GET/DELETE /settings/decision/metrics`),
  a multimodal contract, observability (success log, confidence, signals).
- Runtime settings `/settings/decision` and the UI "Decision models" section (pairs + statistics);
  the `decision` config section without the deprecated `decisionApi`.

### Extensions: Gateway, add-ons, plugins (ADR-086/087/090/068)

- The **Gateway** extension class was introduced and ADR-087 was reworked (messenger gateways as a dedicated class);
  ADR-086 became the "Extensions classes" umbrella.
- The unified extension manifest `synth.pack` (`kind: plugin | gateway | addon | pack`) and types
  of content packs (skills, agents, mcp, themes, i18n, providers, prompts, automation, policies, memory, ui).
- PROP-090 Extension API v1 — design: Plugin ≠ Add-on, plugins in managed (ADMIN) and hybrid (allowlist).
- The `synth` chart: the `installerKey` option (a service key for installing add-ons), declarative `backend.config`,
  `extraObjects`, `persistence.keepOnUninstall` (keep the PVC when the release is uninstalled).

### Onboarding and profile

- Onboarding interview: the `profile_update` tool is granted only to the `assistant` agent (the `user` capability),
  the conditions for injecting the `[INTERVIEW]` block, the `interviewCompleted` status, interview instructions in the prompt.

### Reliability and fixes

- **Reliable Stop**: a persistent `cancelRequested` flag under a lock, graceful cancellation of the active
  stream, stopping the queue processor and exactly one `stream.cancelled` event.
- Event sessions get the instance default agent; the session owner is reassigned
  when delivering into an existing session (answers reach the person).
- Claim flow: correct profile resolution by `username` (used to be `409`).
- Per-key service key rate limit in the core — parity with the backend.
- `POST /events` with a regular Bearer token no longer returns `401` (a correct fallback to `requireAuth`).
- Skills registry cache invalidation after mutations (a real stale read) + a deterministic test.
- Fixed a flake in `core/src/server/app.remote.test.ts` (subscribing to the WS before `open` lost the `connected` frame).
- Ollama: the system prompt is passed as a message, a clearer error for the Qwen3.8 tool chain.
- MCP: the Synth session context is passed into calls via `_meta['synth/session_id']` — external
  MCP servers become session-aware (in the Telegram gateway this yields a correct `chatId`).
- Agents admin panel: a distinguishable display of enabled/disabled capabilities and their full list.
- UI: the service key scopes catalog is taken from the server (with a fallback), deprecated scopes counters were removed.

### Docker: dropping the `latest` tag

Images are now published **with version tags only** — the `latest` tag is no longer pushed.
Reason: the GitVerse "Packages" quota counts the size of each version without deduplication, while `latest` and the version
point to the same digest — that is, they were paid for twice (a 500 MB limit per repository). So the command
without a tag (`docker run gitverse.ru/itphx/synth`) no longer pulls the image — **specify the version**,
as in the "Installation" block below.
