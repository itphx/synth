## 0.13.4 (2026-11-04)

**Stabilization release for the 0.13.x wave — cumulative notes (0.13.0–0.13.4), not a single patch delta.**
150 commits after v0.12.4 (1,101 files, +140,968 / −15,939 lines) publish what has accumulated on the branch:
the message stream v2, the provider compatibility layer, context compaction, streaming attachments, pagination
and light lists. There are no new large subsystems in this release: the goal is to ship what is already written,
close the defects found by the audit and freeze the contracts. Versions 0.13.0–0.13.3 were never published to
npm (only betas in the internal registry), so this document covers the whole wave.

### Release focus — stabilization

- **Contracts over features.** The new message intake, the step stream, the SDK and OpenAPI converge on a single
  specification ([docs/MESSAGE_FLOW.md](../MESSAGE_FLOW.md), [ADR-118](../arch_decisions/adr-118-message-stream-v2.md)).
- **Dogfooding defects fixed.** Shell/“Stop”/roles/step limit, lost steer messages, a duplicate response bubble,
  a stuck indicator after restart, OOM on instance entry and more.
- **The internal security audit was completed before the release** (see below), with the findings closed in this
  same release.

### Message stream v2 (ADR-118)

- **A turn is a sequence of steps, not a single message.** Tool steps (`step.tools`) with metadata and
  deterministic part ids are persisted; old turns are migrated and the feed is restored after a reload.
- **Live state on the server:** a current-step snapshot (`current_stream.live`), activity status and queue state;
  the snapshot is also available for child sessions (sub-agents).
- **Queue and interjection:** a mid-turn message is visible immediately, “Stop” is an interrupt that keeps the
  queue, plus queue reordering, targeted re-fetch and tool-call parity at the step limit.
- **Mutations are addressed by id** (`message.updated`/`message.deleted`) instead of an index; the per-session
  SSE channel is removed — the shared `/ws/events` transport with its fallback remains.
- **Public contract:** OpenAPI for v2 and an updated SDK; an EN version of the API documentation.
- **UI:** steps of a turn are merged into one visual block, “bubble”/“feed” modes, chat density and zoom, response
  expansion, code-block copy/download, lazy shiki highlighting, Markdown code and tables.

### Providers and compatibility (ADR-117)

- **Provider and model compatibility layer:** effort/`reasoningLevel` (Anthropic),
  `cacheFormat`, `requireFinishReason`, advanced parameters in the UI and propagation to hybrid/LLM Proxy.
- **Thinking blocks:** round-trip and signature persistence (multiple blocks), `reasoning_content` for DeepSeek
  thinking models; blocks are never mixed between provider/model pairs.
- **Disabled providers and models** are hidden from selection and are not sent.
- **Usage and cost:** provider response usage, aux accounting, provider cost, sub-agent runtime budget.

### Context compaction (ADR-119)

- **Summarization and compaction** with a token-based tail boundary
  (`summarizationKeepTokens`/`compactionKeepTokens`), window policy, instance defaults, note limits, a UI
  indicator and warnings.
- **The summary is a history message** (`role: summary`) with `summaryOf` and metadata; covered messages are
  hidden, not deleted.
- **Single LLM seam:** compaction always goes through `GatewayProvider` (guard/obfuscation follow the
  `llmGateway` policy; filters/audit/metrics always apply). This is an audit fix: previously, with the gateway
  disabled, the call bypassed the wrapper.

### Attachments (ADR-115)

- **Streaming (chunked) upload**: large files are no longer buffered in memory as a whole; upload-session state is
  stateless and survives replica switches; one-hour TTL and background cleanup.
- **Quotas and limits:** `maxBytesPerSession` now counts active uploads; new
  `attachments.maxActiveUploadsPerSession` (16) and `attachments.maxActiveUploads` (256); an invalid `size`
  returns `400`, an excess returns `413` with `details`. The settings are available in the UI (“Multimodal input”).
- **Processing before sending:** thumbnails, image/video/audio compression at the send boundary (the original in
  the blob is untouched), cache/temp TTLs, limits from the backend, native media via capability rather than a
  host hardcode.
- **Tool attachments** land in the current turn and are shown as a service block.

### API, lists and limits

- **List pagination** (`{items, total, offset, limit, next_offset}`) and summary DTOs; `next_offset: null` means
  the last page; the hybrid mode returns local + remote records.
- **Light sessions:** the list is served without history and queue — this eliminates OOM on entry/recovery;
  `loadLight` in the PostgreSQL driver no longer returns the queue (a defect found by CI and fixed).
- **Read caps:** `fs/read` (5 MiB), `fs/raw` (100 MiB, inline only for media/PDF), listing ≤ 10,000 entries,
  commit diff ≤ 1 MiB; models have hard `limit` bounds.
- **Multi-replica:** chunked upload and hybrid pagination are coordinated across replicas.

### Tools and executor

- **Expanded tool set:** web tools, media, `patch` operations, todo, locks, preview, bounding; `nextOffset` in
  `read_file`, grouped `grep`, a smarter `edit_file` matcher.
- **Write reliability:** CRLF/no-op handling, overwrite protection, atomic writes, `fs.changed` after `patch`,
  clear tool errors, `metadata.i18n` in single results.
- **Policies:** output limit as a setting, `finish_reason`, tolerant tool schemas, shell-guard, configurable
  git/shell/search timeouts.
- **Projects:** atomic `ProjectRepository.mutate` — project edits without lost updates; a single repository
  registry and clear `project_repo_fetch` errors.
- **Executor:** a 600 s timeout ceiling, limits in capabilities, fail-closed `poolLimits`, toolchain tiers
  (`media`, tier 5) and build images.

### Sessions, projects and UI

- **Auto-title** right after the first message, with false-name protection and manual regeneration.
- **Composer drafts**, PWA auto-update, cross-client mutation sync (messages, project, plan, workspace) — the feed
  no longer “sticks” after another client acts.
- **Queue after restart:** auto-resume, a shutdown warning, turn-marker cleanup and a stuck-indicator fix.
- **Project files:** media and rendered Markdown preview, image zoom, heading anchors, relative links in READMEs.

### Hybrid and TLS

- **System TLS trust** in the hybrid client: OS roots supplement the built-in ones, `rejectUnauthorized` is on by
  default; a stable replica id and the right-hand panel.

### Release process and the beta channel

- **Beta packages:** `scripts/publish-beta.sh` (8 packages, `beta`/`next` dist-tags, `latest` does not
  move), the `Beta packages` workflow, `scripts/beta-prune.sh` retention; `@beta` installation is smoke-tested.
- **Release-notes gate:** without the `docs/releases/<version>.md` + `.en.md` pair the artifact build does not
  start.
- **ADR/PROP policy:** the index and the document lifecycle are fixed by rules and `pnpm adr:check`.

### Security

- **Pre-release internal audit** ([docs/security/README.md](../security/README.md)): secret-scan of the tree and
  history, the negative session authorization matrix, the dependency ratchet, a class review.
- **Fixed in this release:** git path containment on the HTTP layer (realpath + a check before destructive
  operations), compaction through `GatewayProvider`, chunked-upload quotas, removal of debug scripts from git,
  the Helm secret-volume mode (`0440` with `fsGroup`, `0444` for compatibility only).
- **Dependencies:** critical 0, high 0 (a clean prod audit); `fast-uri`, `ip-address`, `qs`, `js-yaml`,
  `brace-expansion`, `source-map-js`, `vitest`, `@hono/node-server` were raised.

### Upgrade and compatibility

- **The data schema is extended** by migrations 028–030 (reasoning signature, step stream v2, session retry): when
  upgrading from 0.12.x run `synth migrate` (for PostgreSQL — before starting the new version).
- **Transport:** the per-session SSE channel is removed; clients use `/ws/events` (the SSE fallback remains at the
  shared transport level).
- **Configuration:** the new `attachments.maxActiveUploads*` fields have defaults — existing configs stay valid.
- **Known limitations:** ADR-118 stage 5 (SDK major, removal of `message.added`, webhook subscriptions on the new
  model) is out of scope for 0.13.4; an instance restart still interrupts an active turn (the cheap HA part is in
  the next release); JSON logs with `request_id` and the SLO minimum are also beyond this release.
