## 0.13.8 (2026-11-11)

**Кумулятивный релиз волны 0.13.x — заметки за весь диапазон v0.13.4..HEAD (более 120 коммитов), а не дельта одного патча.**
Версии 0.13.5–0.13.7 в npm не публиковались (выходили только беты во внутреннем npm-реестре),
поэтому этот документ описывает всю волну.

Главное в 0.13.8 — инстанс научился обслуживать себя сам: агент из чата видит и чинит свой инстанс
(self-help-инструменты, реестр MCP, проекты и сессии), владелец получает штатный канал обновлений
с выбором канала и сервис systemd `--user` для постоянной работы. Второй сюжет — полоса
подтверждений: запрос показывает, **что именно** вызвало вопрос, «Разрешить в сессии» выдаёт
грант по каталогу виновника, а ожидания подтверждений переживают рестарт инстанса.

### Фокус релиза

- **Агент обслуживает свой инстанс** ([ADR-131](../arch_decisions/adr-131-self-management-tools.md)):
  `synth_info`, `synth_mcp_*`, поиск проектов и сессий — без curl, ручного разбора `dist` и без
  чтения секретов. Встроенный скилл `/instance` — runbook прямо в чате.
- **Обновление и постоянная работа — штатные сценарии**
  ([ADR-133](../arch_decisions/adr-133-update-channels.md),
  [ADR-134](../arch_decisions/adr-134-instance-service-systemd-user.md)): каналы `stable`/`beta`,
  `synth service` (systemd `--user`), перезапуск из UI/CLI по exit 75.
- **Полоса подтверждений стала понятной и переживает рестарт**
  ([ADR-029](../arch_decisions/adr-029-granular-permissions.md)): структурный «виновник»,
  подсветка токена в команде, грант каталогом, персистентные ожидания подтверждений.
- **Standalone догнал managed по составу API**: реестр MCP и остальные backend-only роуты живут
  в core ([ADR-071](../arch_decisions/adr-071-mcp-servers-prompt.md) §2.5).
- **Капы инструментов поиска и чтения** — после инцидента, в котором одна минифицированная строка
  унесла в контекст 243 КБ.

### Self-help инструменты инстанса, MCP и проектов/сессий (ADR-131)

Новый capability `instance` и группа разрешений: read-тулы доступны в режиме `plan`, write-тулы
(`synth_mcp_add`/`update`/`remove`/`enable`) — нет.

- **Инструменты инстанса:** `synth_info` (версия, режим, каталог данных, флаги аутентификации,
  backend хранилища, счётчики) и `synth_mcp_list`/`synth_mcp_test` — реестр MCP, статус, эффективный
  scope, причина и политика. **Секреты не читаются и не возвращаются:** у аутентификации только
  флаги (`localKeyPresent`, `apiKeyConfigured`), URL редактируется, `headers`/`env` не выдаются.
- **Управление MCP:** `synth_mcp_add`/`update`/`remove`/`enable`/`reconnect`. Запись уровня
  `instance` и `stdio` — только `ADMIN`; пользовательские HTTP/SSE-серверы проверяются сетевой
  политикой MCP; добавленный сервер **не** включается в сессию автоматически (opt-in).
- **Auto-reconnect:** истёкшая MCP-сессия (`Session not found`) переподключается один раз и
  повторяет вызов; `synth_mcp_reconnect` — ручной путь.
- **Проекты и сессии:** `list_projects`, `get_project`, `list_sessions`, `get_session_info`,
  `session_rename` — компактные сводки без истории сообщений, лога проекта и секретов.
  `project_attach` принимает **id или точное имя**; при неоднозначности возвращает кандидатов и не
  выбирает молча. В гибриде discovery сливает локальный и удалённый миры (`origin`, id вида
  `remote:<uuid>`, `remote_offline`/`remote_truncated`), но cross-world перенос запрещён.
- **Скилл `synth-instance`** (команда `/instance`, триггер `auto`) — runbook: что за инстанс, какие
  MCP, как добавить/включить/переподключить, как найти проект и сессию.
- **CLI `synth mcp list|add|test|remove|reconnect`** — тонкий клиент локального API; ключ читается
  внутри процесса и не печатается. `synth config show` по умолчанию редактирует секреты
  (раскрытие — только явным `--show-secrets`).

### Каналы обновлений (ADR-133)

- **Канал выводится из установленной версии** (`-beta.` ⇒ `beta`, иначе `stable`); override —
  секция `updates` в конфиге или env `SYNTH_UPDATES_*`. Отдельного файла-маркера нет: состояние
  не расходится с фактом установки.
- **Источники по каналу:** `stable` — dist-tag `latest` из npmjs, `beta` — dist-tag `beta` из
  npm-реестра Gitea. **Бета-реестр читается без токена** — токен нужен только для публикации.
- **Автопроверка выключена по умолчанию** (`updates.check: false`): офлайн-инстанс не шумит
  запросами. Явная проверка (`synth update --check`, кнопка «Проверить») работает всегда и кэш
  игнорирует; кэш живёт 24 ч, запись с ошибкой — 1 ч, офлайн деградирует тихо.
- **Установка — только явное действие** и только при user-level npm prefix: системную/root-установку
  команда не трогает. В Docker/Helm/managed self-update запрещён (`409 UPDATE_UNSUPPORTED`).
- **Переход `beta → stable` — это откат:** помечается и требует подтверждения, а не «обновления».
- **CLI:** `synth update --check|--apply|--channel auto|stable|beta|--registry <url>|--to <version>
  --dry-run|--json`; **UI:** блок «Обновления» в «Панели управления» (канал, тумблер автопроверки,
  «Проверить», «Обновить» + чекбокс рестарта). Применение идёт через SSE-поток установки, рестарт
  инстанса планируется автоматически.

### Сервис инстанса: `synth service` и systemd `--user` (ADR-134)

Единственный поддерживаемый путь провижининга «пусть работает всегда» — вместо самодельного unit.

- **Команды:** `install|status|start|stop|restart|enable|disable|logs|uninstall`, флаги
  `--print-unit`/`--dry-run`/`--json`/`--force`/`--no-autostart`/`--no-start`/`--no-linger`.
  Установка ждёт `GET /health`; в выводе — пути unit и env-файла, URL и **путь** к API-ключу
  (без значения; в журнал systemd ключ тоже не печатается).
- **Фиксированный шаблон unit:** `Restart=on-failure`, `RestartForceExitStatus=75`,
  `RestartSec=3`, `KillMode=mixed`, `TimeoutStopSec=30`, `SYNTH_RESTART_MODE=process`,
  `EnvironmentFile` (`0600`, без секретов) и маркер `# Managed by synth service install` — чужой unit
  не перезаписывается без `--force`.
- **Linger** (`loginctl enable-linger`) включается best-effort: без него сервис живёт до выхода из
  сеанса и не стартует после перезагрузки; неудача — предупреждение, а не ошибка.
- **Только `--user`:** root/system-контур не поддерживается (модель «один пользователь — свои
  инстансы»). На не-systemd платформах команда сообщает о неподдерживаемости.
- **Гибрид:** unit не содержит токенов — авторизация через сохранённые credentials после
  `synth connect` (device flow).
- **Перезапуск по exit 75** теперь работает «из коробки»: `POST /api/v2/maintenance/restart
  {confirm:true}` (или `synth service restart`) завершает процесс кодом 75, супервизор поднимает
  новый. В npm-CLI добавлен `synth serve --restart-mode disabled|process|supervisor`.

### Подтверждения прав: полоса, гранты и переживание рестарта (ADR-029)

- **Структурный «виновник»** (`messageId`/`params`/`matchedRule`/`askKind`) доезжает до UI в
  событии `permission.asked` и в DTO восстановления — полоса показывает, **что** вызвало вопрос,
  и подсвечивает токен-виновник прямо в команде и в причине. Причина переведена на человеческий
  язык, команда вынесена отдельным блоком, технические детали свёрнуты.
- **Грант считается по сегменту-виновнику:** командные шаблоны («на всю команду») не выдаются
  вообще — такой шаблон шире одобренного (для `rm -rf /srv/data` это был бы вечный `rm *`).
  Вместо них по динамическому ask'у (непроверяемый glob, `$(...)`) предлагается каталог виновника,
  и в сессию пишется правило `external_directory: "<dir>/*" = allow`. Снять вопрос можно только если
  все фактические совпадения glob'а внутри периметра или под **явным** правилом
  `external_directory`; `protected`/`mutation`/`cwd`/`deny` не снимаются никогда. Выдача гранта
  пишется в аудит (`scope=permission`, `action=grant`) вместе с каталогами.
- **Ожидания подтверждений переживают рестарт инстанса:** отдельный порт слоя хранения
  (`{dataDir}/pending-approvals.json`; PostgreSQL — таблица `pending_approvals`, миграция 034).
  После рестарта ожидание приходит как восстановленное: `allow` применяется как грант в сессии,
  `deny` снимает его, `hold` → `400`. В DTO сессии появился счётчик `pending_approvals`, в UI —
  пометка «инстанс был перезапущен».
- **Грант по восстановленному ожиданию не шире одобренного.** «Разрешить в сессии» на ожидании,
  пережившем рестарт, считается по тому же плану, что и на живом: динамический путь даёт грант
  каталогом, а `mutation`/`protected`/`cwd` грантом не снимаются — вопрос повторится. Если снимка
  причины нет, для команд оболочки грант не выдаётся вовсе (fail-closed).
- **Индикатор в дереве сессий:** статус `approval` — оранжевая точка **и** название, а не только
  цвет; цвет — не единственный сигнал.

### Реестр MCP и backend-only роуты перенесены в core (ADR-071 §2.5)

- Standalone больше не отдаёт `404` на `/api/v2/mcp/registry*`.
- **Реестр — источник истины в обоих режимах:** в standalone серверы из `config.mcpServers`
  сидируются в реестр при старте (`seedFromConfig`, идемпотентно), менеджер MCP наполняется из карт
  реестра — правка реестра больше не стирает серверы из конфига.
- В core переехали также: `/logs/:name` и `/logs/llm`, `/audit` и `/audit/revealed`,
  `/gateway/patterns`, `/context/files*` и `/context/enabled`, `/admin/debug/config`,
  `POST /providers/fetch-icon`. Различаются только guard'ы и тексты.

### Признаки инстанса объявляет сервер (`/meta`, ADR-118 §8)

- Инстанс сообщает в `GET /api/v2/meta`, какие опциональные контуры он обслуживает
  (`features.users`); UI-разделы настроек объявляют нужные им фичи (`requiresFeatures`) и
  скрываются, если сервер фичу не обслуживает. Раньше UI угадывал по типу развёртывания и ломался
  в гибриде.
- Единая точка обращения к `/meta` — `instanceCapabilitiesStore` (TTL 60 с + дедуп); раньше к
  `/meta` ходили два разных пути.
- Allowlist публичных путей перенесён в core (единственный источник правды для обеих сборок).

### Капы инструментов поиска и чтения

- **Кап строки — 2000 символов** для `grep_files` и `read_file` (маркер `search.line_truncated`);
  счётчик `metadata.matches` теперь реальный.
- **Общий предел вывода тула отменять нельзя:** флаг `metadata.truncated`, который тул ставил сам,
  убран — инструмент больше не может отключить лимит; маркеры усечения переносятся в хвост
  (`metadata.truncationNote`).
- **Поиск не заходит в мусор:** исключены каталоги `node_modules`, `dist`, `build`, `out`,
  `coverage`, `.venv`, `venv`, `__pycache__`, `.next`, `.turbo`, `.cache` и файлы `*.map`, `*.min.js`,
  lock-файлы. Явный путь важнее исключения; скрытые совпадения не теряются молча — маркер
  `search.matches_excluded` и `metadata.excludedMatches`. `glob` и `list_directory` не затронуты:
  перечисление отвечает на вопрос «что есть в проекте».
- Регресс инцидента: 242 999 → 1 930 символов; гигантская строка 236 564 → 2 097.

### SSH-доступ к удалённым хостам (ADR-124)

- Per-agent ключи хранятся зашифрованно (`secrets/ssh-keys/`); два режима — `tools`
  (`ssh_exec`, `ssh_copy`, `ssh_tunnel`) и `agent` (эфемерное форвардинг-агента); в образах
  появились `ssh`/`rsync`.
- Ключ без завершающего `\n` больше не ломает `ssh-add`, `user` обязателен для SSH-тулов, агент
  работает в foreground-режиме.

### Серверные MCP-серверы в локальных сессиях гибрида (ADR-125)

Локальные сессии могут использовать серверный реестр MCP (прокси уровня инструментов и relay
протокола) по тем же правилам включения и scope, что и удалённые; существующие проекты сидируются
идемпотентно, неудачный relay деградирует до уровня инструментов с указанием причины.

### Параллельное исполнение инструментов в шаге (ADR-127)

Независимые вызовы одного шага исполняются конкурентно (паритет с opencode), порядок событий
шага остаётся объявленным; мутирующие вызовы (`plan_*`, `project_*`) сохраняют барьер — следующий
сегмент ждёт их.

### Компактизация на границе шага (ADR-128)

Сжатие контекста срабатывает на границе шага, когда окно почти заполнено, а не в конце хода;
провал или деградация сжатия сообщаются явно, а не остаются незамеченными.

### Списки задач дочерних сессий (ADR-129)

Саб-агент ведёт собственный список (`task.todos` при старте, `todo`-capability, `<todos>` в
результате и в уведомлении о фоне) и не сливается со списком родителя.

### Рабочая панель: план, ToDo, журнал, инварианты (ADR-130)

Компактные списки в правой панели, модальное рабочее пространство (доска / ToDo / журнал /
инварианты / статистика), Markdown-редакторы, точечный API с событиями и кнопка в шапке.
Журнал проекта вынесен из детали проекта; для `remote:`-проектов и сессий план, журнал, инварианты
и ToDo форвардятся на удалённый backend.

### Лимит тяжёлых операций и пакетный импорт (0.13.7)

Лимит тяжёлых операций настраивается (`limits.sessionOpsPerMinute`, runtime-настройка «Безопасность
→ Лимиты запросов», применяется без рестарта). Пакетный импорт сессий дедуплицирует записи по
`source_session_id`; публикация проекта переносит сессии уровнями зависимостей одним запросом на
уровень.

### Безопасность

- **Shell-guard:** закрыты обходы deny-листа (слитные перенаправления, вложенные исполнители,
  шелл-префиксы, heredoc, `/proc/<pid>/root`, позиционные параметры) — и одновременно убраны ложные
  ask'и (аргумент-паттерны `sed`/`grep`/`awk`/`jq`, значения `find`, workspace-глобы, переменные из
  `NAME=value`/`for`/`read`). Динамическое имя команды раскрывается, когда биндинги дают конечный
  набор простых значений.
- **Грант сессии не расширяет запреты:** он снимает только динамический ask; `deny`,
  `approvalPaths`, find-мутации и динамический `cd` остаются в силе. Грант выдаётся каталогом
  (`external_directory: "<dir>/*" = allow`), а не шаблоном «на всю команду»; для
  `mutation`/`protected`/`cwd` и при неизвестной причине правило в сессию не пишется вовсе —
  остаётся только разовое разрешение.
- **Auth-граница:** единый fail-closed гейт `/api/*` с общим allowlist публичных путей по
  методу+пути в core — роутер, смонтированный без guard'а, анонимным не становится; перепись
  доступа ко всем роутерам падает при появлении `:id`-маршрута вне матрицы.
- **API-ключи:** роли задаются `auth.apiKeyRoles` (по умолчанию `USER`, ADMIN — только явно),
  сравнение ключа постоянное по времени; обходы deny-листа shell-guard и границы сессий закрыты
  (P0-аудит 0.13.4, находки F3–F13).
- **Секреты:** ключ инстанса не печатается в журнал systemd и в выводе CLI; `synth config show`
  редактирует секреты; allowlist secret-scan расширен только dummy-фикстурами SSH-ключей
  (исключительно для тестов).
- **Внутренний аудит 0.13.8 проведён**, и обе найденные в этой волне проблемы закрыты в коде **до
  релиза**, а не приняты как риск:
  - *Грант восстановленного подтверждения был шире одобренного.* Ответ «Разрешить» на ожидание,
    пережившее рестарт инстанса, выдавал постоянный сессионный грант целиком (например, команда
    `rm -rf /srv/data` превращалась в правило `rm *`, включая mutation-операции, где грант
    запрещён). Теперь восстановленная ветка считает грант по тому же плану, что и живая, — по
    сохранённому снимку причины; если снимка для команды оболочки нет, правило не пишется вовсе
    (fail-closed). Для администратора: **после рестарта выданный грант не расширяется** — динамика
    закрывается каталогом, а `mutation`/`protected`/`cwd` грантом не снимаются.
  - *Обход общего предела вывода тула.* Предел можно было отключить флагом, который тул ставил сам
    (`metadata.outputBounded`), — плагинный тул мог унести в контекст сотни килобайт. Теперь предел
    считается по фактическому размеру вывода, а поддельные счётчики перезаписываются. Для
    администратора: **предел вывода нельзя отменить из тула**.
- **Запись аудита приложена к релизу** (`docs/security/releases/0.13.8.json`) и финализируется
  гейтом при тегировании; остаточные принятые исключения предыдущей волны ведутся в той же записи.
  Политика и процедура аудита — [docs/security/README.md](../security/README.md).

### Исправлено

- **Профиль в standalone** (`GET/PUT/PATCH/DELETE /auth/profile`) — сохранение профиля больше не
  требует managed-контура.
- **LLM-ошибка `internal server error` внутри 400-обёртки провайдера** классифицируется как
  `server_error` и считается восстановимой: ход ретраится, а не умирает. Клиентские 400
  (`no_user_query`, `validation`, `context_length`, `auth_error`) остаются невосстановимыми.
- **Одна перезагрузка после обновления/рестарта** вместо двух: сброс кэшей шелла, одноразовая
  метка и тихий `SKIP_WAITING` ожидающего service worker'а.
- **Доступность скиллов** считается по capabilities агента: в DTO добавлен `missingCapabilities`,
  «недоступен» больше не показывается ложно.
- **Установка из бета-реестра** ставится scoped-ключом `--@itphx:registry` — публичные зависимости
  больше не тянутся из закрытого реестра.
- **Мобильная полоса подтверждений** помещается в экран (таймер и действия переносятся), команды
  не разворачивают heredoc на весь экран; причина для кода на stdin читается по-человечески;
  подсказка опросника появляется после первой попытки.
- **Локализация:** подзаголовок пустого экрана переведён, форма worktree в русских строках
  приведена к инвариантной.
- **Прочее:** устранён застрявший streaming-шаг (в данных, а не только в UI), терминальный
  статус шага не откатывается поздним драфтом, починен курсор пагинации для legacy-сессий с
  неуникальным `seq`, восстановлена индикация потери связи в PWA, права управления проектом в
  локальном мире гибрида больше не блокируются для обычного `USER`, публикация проекта в гибриде
  не упирается в таймаут 15 с и показывает прогресс в процентах.

### Обновление и совместимость

- **Схема данных расширена** миграциями 031–034 (политика SSH-ключей, remote-режим MCP,
  `source_session_id` для дедупликации импорта, `pending_approvals`). При обновлении с 0.13.4
  выполните `synth migrate` (для PostgreSQL — до старта новой версии).
- **Конфигурация:** новые поля `updates.*` и `limits.sessionOpsPerMinute` имеют дефолты — существующие
  конфиги валидны. Приоритет: env > runtime (UI) > `config.yaml` > дефолты.
- **Контракты API расширены аддитивно:** `permission.asked` и DTO восстановления получили
  `trigger`, `commands`, `saveDirectories`, `restored`; DTO сессии — `pending_approvals`; `/meta` —
  `features`; `/api/v2/updates/*` и `/api/v2/settings/updates` — новые маршруты. Старые клиенты
  продолжают работать.
- **Известные ограничения:** cross-world перенос проектов и слияние remote-MCP не реализованы
  (ADR-131); обновление и перезапуск по-прежнему прерывают активный ход; self-update доступен
  только standalone. `PROP-133` (доступ к проекту) — предложение, в релиз не входит.
