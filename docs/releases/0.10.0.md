## 0.10.0 (2026-10-14)

Крупный релиз платформы: **внешние события и автоматизация**, **расписания**, **публичная API-платформа**
(service-key + scopes, webhooks, OpenAPI, SDK), **decision-модели** и **Telegram-шлюз** как отдельный класс
расширений. 107 коммитов после v0.9.0.

### Внешние события и автоматизация (AD-089)

- Ядро: `HookBus` (AD-030, минимальный срез) и сущности `Event`/`EventBinding`/`Router`; создание
  сессий сведено к единому funnel `RequestSessionService` (`direct` — явный запрос, `external_event` — через Router).
- Правила маршрутизации `match → target` (`bound`/`queue`/`ephemeral`), резолвинг `agentTemplate`,
  режим по умолчанию (`bound`/`ephemeral`) и журнал решений Router.
- **API-ключи привязок**: обязательная уникальная метка, срок и лимит запросов, мягкий отзыв,
  per-key и глобальный rate limit, каскадное удаление вместе с привязкой.
- **auto-bind**: при `events.autoBind` Router сам создаёт привязку для чата/треда (общие чаты,
  без ручной настройки).
- **Идентичность и видимость**: внешние идентичности хранятся в профиле, claim-flow с одноразовым
  кодом, редактор `identityMap`; владелец сессии — человек (а не чат), поэтому сессии из мессенджеров
  видны в UI владельца; списки сессий/проектов учитывают владельца, участников проекта и сквозной обзор ADMIN/LEAD.
- **Права внешних отправителей**: база — роли профиля владельца, роли из шлюза только **сужают**
  (пересечение), несопознанный отправитель прав не получает (fail-closed); эффективные роли пишутся
  в метаданные сообщения для аудита.
- Retention журнала событий (pruner), runtime-настройки раздела «События» (мастер-выключатель,
  TTL ephemeral-сессий, источники, шаблоны агентов).
- UI: пользовательский раздел «События» (привязки, ключи с однократным показом секрета, журнал),
  админ-секция «Параметры событий», журнал продублирован в «Логи и аудит».

### Расписания (AD-051)

- Источник `cron`: планировщик публикует `schedule_fired` через Router и **не создаёт сессии сам**;
  CRUD расписаний (`PUT` для обновления), History, force-запуск, catch-up.
- Сообщения планировщика идут от системного пользователя `Scheduler`, в UI отображаются центрированным
  Notice, в LLM добавляется поясняющий volatile-блок `scheduler.turn`.
- Семы мульти-инстанса (leader election, атомарный dedup-claim, межпроцессные локи, file-based
  реализации) — по умолчанию **выключены**.

### Публичная API-платформа (AD-052, этапы I–IV — закрыта)

- **Service-key** со `scopes` и проектной проекцией `allowedProjects`: выпуск/отзыв/лимиты, паритет
  RBAC и scopes в ядре и backend, каталог scopes отдаётся сервером (`GET /service-keys/scopes`).
- **Webhooks**: подписки на события, HMAC-SHA256-подпись (`X-Synth-Signature`) с окном приёма,
  retry/backoff с джиттером, дедупликация, SSRF-политика, журнал доставок, ротация/отзыв секрета.
- **Public OpenAPI**: интеграционное ядро и 28 операций на `@hono/zod-openapi`, именованные модели,
  единый формат ошибок.
- **SDK** `@itphx/synth-sdk` — типизированный клиент публичного API (новый пакет в монорепо).
- Фикс доставки: ответы сессий не доходили клиентам со service-key/elevated — включён режим
  watch-all для SSE/WS.
- Scope `addons:install` (+ `users:read`) и бутстрап service-key — для установки аддонов.

### Decision-модели (AD-084 — закрыта)

- Класс decision-моделей: провайдеры-протоколы `decision` и `systemone`, микро-каскад, decision-классификация
  маршрутизации (в т.ч. для внешних событий).
- Эскалация `primary → escalation`, агрегатные метрики decision-слоя (`GET/DELETE /settings/decision/metrics`),
  мультимодальный контракт, наблюдаемость (лог успеха, confidence, signals).
- Runtime-настройки `/settings/decision` и UI-секция «Decision-модели» (пары + статистика);
  секция конфига `decision` без устаревшего `decisionApi`.

### Расширения: Gateway, аддоны, плагины (AD-086/087/090/068)

- Введён класс расширений **Gateway** и заново оформлен AD-087 (мессенджер-шлюзы как отдельный класс);
  AD-086 стал зонтиком «Классы расширений».
- Единый манифест расширений `synth.pack` (`kind: plugin | gateway | addon | pack`) и типы
  контент-паков (skills, agents, mcp, themes, i18n, providers, prompts, automation, policies, memory, ui).
- AD-090 Extension API v1 — дизайн: Plugin ≠ Add-on, плагины в managed (ADMIN) и hybrid (allow-list).
- Чарт `synth`: опция `installerKey` (service-key для установки аддонов), декларативный `backend.config`,
  `extraObjects`, `persistence.keepOnUninstall` (сохранять PVC при удалении релиза).

### Онбординг и профиль

- Онбординг-интервью: тул `profile_update` выдан только Агенту `assistant` (capability `user`),
  условия инжекта блока `[INTERVIEW]`, статус `interviewCompleted`, инструкции по интервью в промпте.

### Надёжность и исправления

- **Надёжный «Стоп»**: персистентный флаг `cancelRequested` под локом, graceful-отмена активного
  стрима, остановка процессора очереди и ровно одно событие `stream.cancelled`.
- Событийные сессии получают агент по умолчанию инстанса; владелец сессии переустанавливается
  при доставке в существующую сессию (ответы доходят до человека).
- claim-flow: корректный резолв профиля по `username` (был `409`).
- Per-key rate limit service-key в ядре — паритет с backend.
- `POST /events` с обычным Bearer-токеном больше не отдаёт `401` (корректный fallback на `requireAuth`).
- Инвалидация кэша реестра скиллов после мутаций (реальный stale-read) + детерминированный тест.
- Устранён флейк `core/src/server/app.remote.test.ts` (подписка на WS до `open` теряла кадр `connected`).
- Ollama: system-промпт передаётся сообщением, понятная ошибка tool-цепочки Qwen3.8.
- MCP: контекст Synth-сессии прокидывается в вызовы через `_meta['synth/session_id']` — внешние
  MCP-серверы становятся session-aware (в Telegram-шлюзе это даёт корректный `chatId`).
- Админ-панель агентов: различимое отображение включённых/отключённых capability и их полный список.
- UI: каталог scopes service-key берётся с сервера (с фоллбеком), убраны устаревшие счётчики scopes.

### Docker: отказ от тега `latest`

Образы теперь публикуются **только с версионными тегами** — тег `latest` больше не выкладывается.
Причина: квота «Пакеты» в GitVerse считает размер каждой версии без дедупликации, а `latest` и версия
указывают на один digest — то есть оплачивались дважды (лимит 500 МБ на репозиторий). Поэтому команда
без тега (`docker run gitverse.ru/itphx/synth`) больше не качает образ — **указывайте версию**,
как в блоке «Установка» ниже.
