# Документация Synth

Два контура: пользовательский портал (`synth-docs`) и dev-доки в монорепо (`synth/docs`, `AGENTS.md`, AD). Источник истины по фактам — **код**, `AGENTS.md` и AD; документация — производная.

## Когда применять

- Правка или добавление любой документации Synth (портал, `synth/docs`, `AGENTS.md`, AD, README, лэндинг).
- Перенос материала между порталом и репозиторием.
- Изменился факт (поведение, конфиг, CLI, окружение, путь, роль), отражённый в доках.
- Правка лэндинга, ведущего на портал.

## Два контура документации

| Аудитория | Репозиторий / каталог | Где публикуется | Канонический источник |
|---|---|---|---|
| Пользователи | репо `synth-docs` (`git@git.itphx.loc:itphx/synth-docs.git`, **приватный**), MkDocs Material | `https://docs.synth.itphx.ru/` (внешний), `https://synth-docs.k3s.itphx.loc/` (внутренний) | портал — пользовательский контент здесь не дублируется |
| Разработчики | `synth/docs/` (`ARCHITECTURE`, `CONFIGURATION`, `DEVELOPMENT`, `PUBLISHING`, `API_V2`, `ROUTING`, `KEYCLOAK`, `LLM_PROVIDERS`, `TROUBLESHOOTING`), `AGENTS.md` (корневой и пакетные), `docs/arch_decisions/` | в репозитории (не публикуется как сайт) | код (`path:line`), `AGENTS.md`, AD |
| Витрина | репо `synth-landing` | `https://synth.itphx.ru/` | продуктовая подача; ссылки ведут на портал |

## Распределение контента

- **В портал:** how-to, установка, настройка, режимы, CLI, FAQ, диагностика — пользовательское.
- **В репозиторий:** внутренности, AD, CI/публикация, API-справочник, архитектура движка — для разработчиков.
- Смешанный файл распиливать по аудиториям.
- Пользовательское **не дублировать** в репо. Из репо на портал ссылаться **абсолютными URL**; внутри портала — относительными ссылками.
- При переносе страницы из `synth/docs/` в портал в репо оставлять note-ссылку на портал. Прецеденты: `QUICKSTART`, `CONFIGURATION`, `HYBRID`, `ARCHITECTURE`, `TROUBLESHOOTING`.

## Стиль пользовательского портала

- Русский — RU канонический. EN выключен (`build: false` у локали `en`), включается отдельным этапом после перевода; до этого русские страницы не должны публиковаться под `/en/` через фолбэк.
- Material: тёмная тема по умолчанию, оранжевый акцент `#c33b04`, базовый шрифт JetBrains Mono, левое меню по группам, правый TOC, поиск `Ctrl+K`, ссылка «Редактировать страницу».
- Навигация — 6 разделов: **Обзор; Начало работы; Использование; Развёртывание; Администрирование; Помощь**.
- **Запрещено в пользовательском тексте:** номера AD, ссылки на `AGENTS.md`, внутренние пути `packages/…` (кроме реальных команд запуска), внутренние dev-хосты `*.itphx.loc`, секреты и тестовые ключи, статусы веток/разработки.
- **Допустимо:** публичные URL (`gitverse.ru`, helm-реестр), реальные команды запуска.
- Приёмы: admonitions, табы (`pymdownx.tabbed`), таблицы, grid cards, octicons-ссылки, блок «Что дальше» в конце страницы.

## Согласование основного репо и репо доков

- **Источник истины — код** (`path:line`), `AGENTS.md` и AD. Докам нельзя противоречить коду.
- Изменился факт → синхронизируй: dev-доки (`synth/docs`) при необходимости → страницу портала → `AGENTS.md`/`README` (если процесс/окружение) → лэндинг (если продуктовая подача).
- **Один факт — одно место:** пользовательское в портале, внутренности в репо; противоречий быть не должно (проверять, например, роль локального ключа core = `ADMIN`, версии, пути).
- **Лэндинг:** кнопки «Попробовать» ведут на портал (`https://docs.synth.itphx.ru/`, CTA — `/getting-started/quickstart/`); i18n-баланс `HTML = RU = EN` (единственный программный ключ вне HTML — `lightbox_close`).
- **Коммиты — только по явной просьбе.** Репозитории разные: `synth` → GitVerse, `synth-docs`/`synth-landing` → `git.itphx.loc`.

## Процесс обновления

1. Определить аудиторию и репозиторий (портал / `synth/docs` / `AGENTS.md` / лэндинг).
2. Сверить факты по коду (`path:line`), при необходимости — `AGENTS.md`/AD.
3. Внести правку в стиле соответствующего контура.
4. Локально собрать/проверить (см. ниже и чек-лист).
5. Структурные и стилевые изменения согласовать с пользователем.
6. Коммит/деплой — только по просьбе.

## Сборка и деплой портала

```bash
# Локально (venv + зависимости + сервер)
cd synth-docs
uv venv .venv && uv pip install -r requirements.txt && .venv/bin/mkdocs serve

# Строгая сборка статики (warnings = errors)
.venv/bin/mkdocs build --strict

# Образ и пуш (приватный реестр)
docker build -t git.itphx.ru/itphx/synth-docs:latest .
docker push git.itphx.ru/itphx/synth-docs:latest
```

- Fleet: GitRepo `synth-docs` в namespace `fleet-local` (repo `git@git.itphx.loc:itphx/synth-docs.git`, branch `main`, `clientSecretName: auth-kb424`, polling 1m). Push в `main` → Fleet подхватывает чарт.
- Контент **запечён в образ**, поэтому после пуша образа нужен рестарт: `kubectl -n synth-docs rollout restart deploy/synth-docs`.

### Предусловия и грабли

- Fleet **не читает `.helmignore`** — нужен корневой `.fleetignore` (иначе весь корень уходит в Helm-чарт и release-secret превышает лимит 1 MB).
- В namespace `synth-docs` нужен pull-secret `git.itphx.ru` (docker-registry); создаётся вручную копированием из namespace `synth`.

## Верификация (чек-лист)

- [ ] `mkdocs build --strict` — exit 0, без warning.
- [ ] В `site/` нет каталога `en/`.
- [ ] Все относительные ссылки резолвятся (0 битых).
- [ ] grep-ом нет утечек: `AD-[0-9]`, `AGENTS.md`, `*.itphx.loc`, тестовые ключи.
- [ ] Playwright: тёмная тема, `--md-primary-fg-color=#c33b04`, моно-шрифт, 6 групп навигации, `Ctrl+K`, мобильный дровер, 0 ошибок консоли.
- [ ] Live-URL отдаёт 200.
- [ ] Для лэндинга: sha256 отданного `index.html` == `git show HEAD:index.html`.

## Типичные ошибки

1. Утечка AD, внутренних путей, dev-хостов `*.itphx.loc` или секретов в пользовательский текст.
2. Публикация RU-контента под `/en/` через фолбэк.
3. Битые ссылки при переносе страниц между контуром репо и порталом.
4. Хардкод путей и устаревшие версии (например, `0.3.0` вместо актуальной).
5. Дублирование одного факта в двух контурах вместо ссылки.
6. Коммит без явной просьбы пользователя.
